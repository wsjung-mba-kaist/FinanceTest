## 1. 계층 밖 CSS는 모든 유틸리티를 이긴다

Tailwind v4는 스타일시트 맨 위에서 계층 순서를 선언한다.

```css
@layer properties;
@layer theme, base, components, utilities;
```

CSS 캐스케이드에서 **계층에 속하지 않은 규칙은 모든 계층보다 강하다.** 특이도(specificity)를 비교하기
전에 계층 소속부터 비교하기 때문이다. 그래서 이런 한 줄이

```css
/* 계층 밖 */
a {
  color: var(--accent);
}
```

`class="text-accent-fg"`가 붙은 링크를 **이긴다.** 강조색 배경 위에 강조색 글씨 — 즉 보이지 않는
라벨이다. 실제로 홈 화면의 파란 «이어하기» 버튼이 이 한 줄 때문에 글씨가 안 보이는 채로 배포됐다.

`button { font: inherit }`도 같은 사고다. `font`는 단축 속성이라 `font-size`를 함께 초기화하므로
버튼에 붙은 `text-sm` · `text-lg`가 전부 무효가 된다.

**규칙**: 요소 기본값은 `@layer base`, 컴포넌트 스타일(`.md` 타이포그래피, 애니메이션 클래스)은
`@layer components`.

**예외 세 가지 — 전부 의도적이다.**

| 예외                                  | 이유                                                                                                                            |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `:root…` 토큰 블록                    | 커스텀 속성은 계층 싸움에 참여하지 않는다. `var()`로 읽어 가는 쪽이 이미 이긴 규칙이다.                                         |
| `@media print` 전체                   | 인쇄 규칙의 **존재 이유가** 유틸리티를 덮는 것이다. 계층에 넣으면 `bg-surface`가 `--surface: #fff`를 이겨 종이에 회색이 깔린다. |
| `@media (forced-colors: active)` 전체 | 같은 논리. 강제 팔레트가 지운 경계를 `currentColor`로 다시 그리는 것이 그 블록의 일이다.                                        |

`prefers-reduced-motion` 리셋은 `*`에 `!important`를 거는 의도적 망치라 계층 밖에 둔다.

## 2. 커스텀 `@utility`는 내장 유틸리티보다 **먼저** 방출된다

같은 `@layer utilities` 안에서, 같은 특이도 `(0,1,0)`이면 **소스 순서**가 이긴다. Tailwind는 커스텀
`@utility`를 그 계층의 **맨 앞**에 놓는다. 컴파일된 결과를 직접 보면 이렇다.

```css
@layer utilities {
  .card-key {            /* 커스텀 — 먼저 */
    border: 1px solid var(--border-strong);
    background: var(--surface);
    border-radius: 0.5rem;
    box-shadow: var(--shadow-card);
  }
  .rounded-lg { … }      /* 내장 — 나중 ⇒ 이긴다 */
  .border { … }
  .bg-surface { … }
}
```

결론: **`card-key`는 추가된 날부터 단 한 번도 자기 테두리를 그린 적이 없다.** 같은 요소에
`rounded-lg border border-border bg-surface`가 함께 있으면 네 속성 모두 내장 쪽이 이긴다. jsdom은
스타일시트를 적용하지 않고, 스냅샷에도 안 잡히고, 소스를 읽어서는 알 수 없다. 오직 **방출된
텍스트**에서만 보인다 — 그래서 `cssEmissionOrder.test.ts`가 있다.

**규칙**:

- `@utility`는 **한 가지 목적의 작은 기본값**만 담는다. 덮어쓸 수 있다는 것이 올바른 동작인 경우
  (`prose-col`, `num-lg`, `label-caps`).
- 선은 **속성으로** 긋는다: `@utility`는 **타입과 색**만 칠하고 **박스는 칠하지 않는다.**
  `border` · `background` · `box-shadow` · `outline` · `padding` · `margin` · `gap` · `display` ·
  `width` · `height` · `position` — 전부 항상 지는 규칙이다.
- 여러 속성이 함께 움직여야 하는 «컴포넌트 룩»은 React 프리미티브로 만든다 — `<Card tier="key">`.
  메커니즘이 하나뿐이면 캐스케이드 싸움 자체가 존재할 수 없다.

## 3. JS는 값을 주고, CSS가 계산한다

루트 글꼴 크기를 JS가 `element.style.fontSize`로 직접 쓰면 **인라인 스타일**이 되어 미디어 쿼리를
전부 이긴다. 넓은 화면 보정(`@media (min-width: 1440px)`)도, 인쇄 크기(`@media print`)도 죽는다.

```css
:root {
  --fs-root: 14px;
  --fs-scale: 1;
}
@media (min-width: 1440px) {
  :root {
    --fs-root: 15px;
  }
}
@media print {
  :root,
  :root[data-theme='dark'] {
    --fs-root: 11pt;
  }
}

html {
  font-size: calc(var(--fs-root) * var(--fs-scale));
}
```

JS가 만지는 것은 `--fs-scale` **하나뿐**이다.

```ts
root.style.setProperty('--fs-scale', String(fontScale))
```

부수 효과로 얻는 것: 첫 페인트 리플로가 사라지고(기본값이 이미 `1`), 인쇄물에도 사용자의 글자 크기
설정이 반영되며, 기준값이 세 군데(JS·CSS·`index.html`)에 중복되던 문제가 사라진다.

## 4. 프레임은 px, 측정(measure)은 em

- **폭 토큰**(`--w-shell`, `--w-doc`)은 **px**. 글자 크기를 1.3배로 키운 사용자가 모니터 가로의 30%를
  잃으면 안 된다. 화면 크기는 물리적인 값이다.
- **가독폭**(`--w-prose: 44em`)은 **em**. 44글자는 어느 배율에서도 44글자다.
- **44em을 넓히지 않는다.** 한국어 장문은 줄이 길수록 읽기 어렵다. 넓은 화면의 빈 공간은 글줄을
  늘려서가 아니라 **콘텐츠로** 채운다.

## 5. 대비: 테두리는 한 종류가 아니다

WCAG 1.4.11(비텍스트 대비 3:1)은 **컨트롤을 식별하는 경계**에 적용되지 장식용 모서리에는 적용되지
않는다. 테두리 토큰 하나를 3:1로 밀면 166개의 카드 모서리가 전부 진해져 화면이 스프레드시트가 된다.
그래서 셋으로 나눈다.

| 토큰               | 쓰는 곳                                                | 기준               |
| ------------------ | ------------------------------------------------------ | ------------------ |
| `--border`         | 카드·구분선 등 장식용 헤어라인                         | 보이기만 하면 된다 |
| `--border-control` | 입력·토글·선택 가능한 행 — **경계 자체가 컨트롤인 곳** | 3:1                |
| `--border-strong`  | 강조 패널, 인용 막대                                   | 3:1                |

비활성 상태를 `opacity-50`으로 만들지 않는다. 반투명은 **배경에 따라** 대비가 달라져서 확인 버튼이
보이지 않는 조합이 생긴다. `--disabled-bg` / `--disabled-fg` 토큰을 쓴다.

톤 테두리도 마찬가지다. `border-info/30` 같은 알파 테두리는 1.52~2.08:1이었고, **알파이기 때문에**
다크 표면 위에서는 또 다른 값이 됐다. `--sev-*-border` 다섯 종은 고정색이고 표면 위에서 3:1을 넘는다.

이름 충돌도 여기서 끊었다. `--color-none`은 `bg-none`과 `border-none`을 만들었는데, 둘 다 Tailwind
**내장** 유틸리티(`background-image: none`, `border-style: none`)와 같은 이름이다 — 칠하는 것과
반대로 읽히는 이름이었다. 지금은 `--color-sev-none` → `bg-sev-none`이다.

## 5-1. 간격 한 단계가 앱 전체의 호흡이다

Tailwind의 `--spacing` 기본값 `0.25rem`은 16px 루트를 전제로 4px를 준다. 이 프로젝트의 루트는
14px이므로 그 값은 조용히 **3.5px**이 됐다 — 모든 패딩·갭·마진이 설계된 스케일보다 12.5% 좁았다.
`0.2857rem`이 정확히 4px을 되돌린다.

```css
/* @theme inline 이 아니라 @theme — inline 이면 calc() 에 값이 박혀 서브트리 재조정이 불가능하다 */
@theme {
  --spacing: 0.2857rem;
}
```

간격 유틸리티는 `calc(var(--spacing) * n)`으로 컴파일되므로, **서브트리 하나에 인라인 속성 한 줄**로
리듬 전체를 되돌릴 수 있다. 플레이 화면이 정확히 그렇게 밀도를 지킨다.

```tsx
<div style={{ '--spacing': '0.25rem' } as React.CSSProperties}>
```

## 6. 인쇄는 네 번째 팔레트다

`@media print { :root { … } }`는 특이도 `(0,1,0)`이고 `:root[data-theme='dark']`는 `(0,2,0)`이다.
따라서 **다크 모드 사용자가 인쇄하면 다크 토큰이 그대로 종이에 나온다** — 흰 종이에 1.22:1 글씨와
검은 블록. 셀렉터를 둘 다 적어야 한다.

```css
@media print {
  :root,
  :root[data-theme='dark'] { … }
}
```

그리고 인쇄 블록은 **다크 블록이 재정의하는 모든 토큰**을 다시 선언해야 한다. 하나라도 빠지면 그
토큰만 다크 값으로 새어 나온다. `contrast.test.ts`의 `redeclares every token the dark theme
redefines`가 이것을 지킨다.

## 7. 열 수는 항목 수의 함수다

`grid-cols-3`에 항목 13개를 넣으면 마지막 줄에 칸 하나만 남아 640px가 빈다. 고정 열 수 대신
`gridClass(kind, n)`을 쓴다.

- **R1** `c = min(cmax, n, ceil(n / ceil(n / cmax)))` — 줄 수를 유지하면서 열을 고르게 편다.
  `n mod c === 1 && c > 2`면 첫 항목이 2열을 차지해 고아 칸을 없앤다.
- **R2** `cmax`는 콘텐츠 폭이 정한다: 수치 타일 160px · 링크 240px · 질문 280px · 산문 320px ·
  시나리오 360px. **칩 줄은 그리드가 아니라 `flex-wrap`이다.**
- **R3** 높이가 1.4배 이상 차이 나는 두 패널에 50/50을 쓰지 않는다.

## 7-1. 높이는 계산하지 말고 상속한다

플레이 화면은 한때 `h-[calc(100dvh-3rem)]`이었다. `3rem`은 상태바의 높이를 손으로 적어 둔 것이고,
상태바는 `h-12`였다 — 두 값이 같았던 건 14px 루트와 `--spacing: 0.25rem`의 우연한 산술이었다.
간격 한 단계만 바뀌어도 어긋난다.

지금은 `<html>`부터 아래까지 **정확한 높이의 flex 사슬**이다: 셸이 `h-full overflow-hidden`,
상태바가 `shrink-0`, 나머지가 `min-h-0 flex-1`. 어떤 자손도 조상의 높이를 알 필요가 없다.

## 8. 주 행동은 스크롤 영역 밖에 산다

`sticky`로 버티지 않는다. `sticky`는 **조상 중 하나라도** `overflow: hidden`이면 조용히 죽고, 그
조상은 보통 다른 이유로 붙어 있다. 결정 독의 확정 바가 이렇게 죽어 있었다. 스크롤 컨테이너의
**형제**로 두면 그 버그 계열 전체가 존재할 수 없게 된다.

---

## 9. 스타일만 옮기고 요소 타입은 바꾸지 않는다

마이그레이션에서 `<button>`을 `<a>`로(또는 반대로) 바꾸면 `toBeDisabled()` 같은 단언이 조용히 의미를
잃는다. 시각적으로 링크처럼 보여야 하면 `<Button variant="link">`, 버튼처럼 보여야 하는 링크는
`<Button as="a">` — **보이는 것과 의미를 각각 고른다.**

전체 테스트에 **클래스 이름 단언이 하나도 없다**(전부 role/text 질의). 그래서 카드·칩·배지·radius
교체는 테스트에 보이지 않고, 그 덕분에 대규모 마이그레이션이 가능하다. 이 성질을 깨뜨리지 말 것 —
테스트에서 `className`을 단언하지 않는다.

## 10. 툴팁 안에는 링크도 버튼도 두지 않는다

`role="tooltip"`은 **텍스트만** 담는다. 툴팁은 blur에서 닫히고, Tab이 하는 일이 바로 blur이므로
툴팁 안의 링크는 **키보드로 영원히 도달할 수 없다.** 마우스로만 닿게 하려고 `onMouseDown`에
`preventDefault()`를 거는 것은 그 사실을 덮는 것이지 고치는 것이 아니다.

세 곳이 그랬고, 셋 다 정답이 달랐다.

| 컨트롤               | 문제                      | 답                                                                                                                     |
| -------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 용어(`GlossaryTerm`) | 툴팁 안에 «자세히 →» 링크 | **트리거 자체를 링크로.** 호버·포커스는 정의를 읽고, 활성화는 용어집으로 간다. 툴팁에는 텍스트만 남는다.               |
| `InfoTip`            | 툴팁 안에 «자세히» 버튼   | 액션이 있으면 **디스클로저**(`aria-expanded`). 액션이 없으면 그대로 툴팁.                                              |
| 인용(`Citation`)     | 툴팁 안에 출처 URL        | **팝오버.** `aria-expanded` · Esc로 닫고 포커스를 칩으로 되돌림 · 바깥 클릭으로 닫음(`onBlur`로는 링크 클릭을 먹는다). |

## 11. 접근성 이름은 내용을 **대체한다**

`aria-label`은 요소의 내용을 보조하지 않고 **지운다**. 시나리오 카드에 붙어 있던
`aria-label="SVB 브리핑으로 이동"`은 화면에 보이는 역할·소요 시간·난이도·완료 배지를 전부 없애고
그 한 문장만 남겼다 — 도우려고 붙인 라벨이 카드를 지운 것이다.

**규칙**: 내용이 스스로 읽히면 `aria-label`을 붙이지 않는다. 덧붙일 것이 «무엇을 하는 링크인가»
뿐이라면 `<span className="sr-only">`로 **더한다**.

---

## 12. 차트 글꼴은 숫자지만 상수는 아니다

Recharts는 CSS가 아니라 숫자를 받는다. 그래서 `fontSize: 10`을 그대로 적으면 글자 크기를 1.3배로
키운 사용자에게 **차트만 빼고** 전부 커진다 — 이미 눈을 찌푸리고 보던 축 라벨만 10px에 남는다.
`useChartType()`이 루트 크기에서 같은 단계를 계산하고 하한(10px)을 지킨다.

---

## 13. 라이브 리전은 같은 문장을 두 번 말하지 않는다

스크린리더는 라이브 리전의 텍스트가 **바뀔 때** 읽는다. `setAnnounce('결정을 확정했습니다')`를
연달아 두 번 호출하면 React가 같은 값이라 갱신을 건너뛰고, DOM 텍스트가 그대로이므로 두 번째는
소리 없이 지나간다 — 한 턴에 결정을 둘 확정하면 첫 번째만 안내됐다.

`useAnnouncer()`는 `{message, seq}`를 반환하고 `LiveRegion`이 `seq`를 `key`로 쓴다. 번호는
사용자에게 도달하지 않으며, 오직 노드를 새로 만들기 위해 존재한다.

## 14. 프리미티브는 «룩»과 «행동»을 따로 나눠 담는다

마이그레이션을 끝내고 보니 세 가지 형태가 필요했다. 셋 다 필요한 이유가 다르다.

| 형태            | 언제                                                                                          | 예                                              |
| --------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| **컴포넌트**    | 마크업과 행동을 함께 소유할 수 있을 때                                                        | `<Card>` · `<Chip>` · `<Dialog>` · `<Tabs>`     |
| **클래스 함수** | 요소를 바꿀 수 없을 때 — react-router `<Link>`는 컴포넌트로 감싸면 클라이언트 라우팅을 잃는다 | `buttonClass()` · `cardClass()` · `chipClass()` |
| **훅**          | 마크업은 제각각인데 **행동만** 같을 때                                                        | `useFocusTrap()` · `useTabListKeys()`           |

세 번째가 중요하다. 플레이 화면의 탭 목록 셋(단축키를 가진 정보 탭 · 5개 중 3개만 쓰는 더보기 행 ·
배지가 붙은 하단 내비게이션)은 **진짜로 서로 다른 마크업**이다. 하나의 `<Tabs>`에 `variant`를
세 개 달아 욱여넣으면 프리미티브가 더 나빠진다. 반면 셋이 공유하면서 **셋 다 빠뜨렸던 것**은
방향키와 «탭 정지점 하나»라는 키보드 계약이었다. 그건 훅으로 뽑는다.

**래칫도 그에 맞춰 세야 한다.** `role="tablist"`를 세는 건 틀린 대리 지표였다 — 마크업이 다른 건
정상이니까. 지금 세는 것은 «탭 목록을 그리면서 훅을 쓰지 않는 파일»이고, 그 수는 0이다.

같은 이유로 «버튼처럼 그린 링크»를 세던 패턴은 실제로는 **강조색 카운트 필**만 잡고 있었다.
패턴 이름을 바꾸고 `<CountPill>`로 넷을 합쳤다. **대리 지표가 틀렸으면 숫자를 쫓지 말고 지표를
고친다.**

## 15. 선언한 글꼴은 배달한다

`--font-sans`는 첫날부터 `'Pretendard Variable'`을 1순위로 적고 있었다. 그런데 `@font-face`도,
`<link>`도, `public/fonts/` 안의 파일도, 의존성도 **없었다.** 그래서 이 프로젝트의 주 환경인
Windows에서 한글은 내내 **맑은 고딕**으로, 모든 수치는 **Consolas**로 그려졌다. 설정의
«시스템 글꼴 사용 — Pretendard 대신»은 사용자가 갖고 있지 않은 글꼴과 지금 보고 있는 글꼴 사이를
오가는 토글이었다.

**무엇도 이걸 잡지 못한다.** 스타일시트는 유효하고, 캐스케이드도 맞고, jsdom은 애초에 글꼴을
해석하지 않으며, 스크린샷은 그저 «조금 덜 예쁠» 뿐이다. 그래서
[`fonts.test.ts`](../tests/ui/fonts.test.ts)가 «`--font-sans`의 첫 패밀리를 진입 모듈이 실제로
불러오는 스타일시트가 선언하는가»를 단언한다.

동적 서브셋(`pretendard/dist/web/variable/pretendardvariable-dynamic-subset.css`)을 쓴다. 2MB짜리
가변 폰트가 92개 `unicode-range` 조각으로 갈라져 있어 **화면에 실제로 나온 글자 구간만** 받는다.
브라우저로 잰 실비용은 홈 142KB · 지식 베이스 121KB · 용어집 80KB이고 그 뒤로는 캐시다.

### 15-1. 숫자에 필요한 것은 *고정폭*이지 *모노스페이스*가 아니다

`num` 유틸리티는 `--font-mono`를 지정하고 있었고, 그건 실제로는 Consolas였다. 약 230곳에서
한글 라벨 옆에 라틴 코드 글꼴이 붙어 x-height·굵기·색감이 전부 어긋났다. 열을 읽히게 만드는 성질은
`font-variant-numeric: tabular-nums` **하나**이고, Pretendard는 그걸 갖고 있다. 지금 `num`·`num-md`·
`num-lg`는 전부 `--font-sans` + `tabular-nums`다. `--font-mono`에 남은 일은 **진짜 코드**뿐이다
(`.md code`).

`num-lg`·`num-md`는 크기를 `var(--text-xl)`·`var(--text-lg)`로 **읽는다.** rem을 박아 두면 타입
스케일을 바꿀 때 이 둘만 조용히 뒤처진다 — 움직이지 않는 것이 아니라, 아무도 모르게 안 움직인다.

> `@utility`는 선언 6개가 상한이다(`stylesheetLayers.test.ts`). `num-lg`가 `font-feature-settings`
> 까지 달면 7개가 되므로, 레거시 쌍둥이 속성은 `num`에만 남겼다.

## 16. 밀도와 글자 크기는 **직교 축**이다

시력은 «얼마나 큰가»의 문제이고 `--fs-scale`이 답한다. 한 화면에 얼마나 담고 싶은가는
«얼마나 촘촘한가»의 문제이고, 둘을 슬라이더 하나에 합치면 **어느 쪽도 답하지 못한다.** 실무 데스크는
조밀한 화면을 원하고, 내용을 처음 배우는 사람은 여백을 원하는데 둘 다 글자는 같은 크기로 보고 싶다.

```css
:root {
  --sp-base: 0.2857rem;
  --lh-body: 1.55;
  --lh-prose: 1.7;
}
:root[data-density='compact'] {
  --sp-base: 0.25rem;
  --lh-body: 1.5;
  --lh-prose: 1.6;
}
:root[data-density='comfortable'] {
  --sp-base: 0.3214rem;
  --lh-body: 1.65;
  --lh-prose: 1.8;
}
@theme {
  --spacing: var(--sp-base);
}
```

장문 행간이 본문보다 넓은 것은 취향이 아니다. 한글은 같은 글자 수에 담는 정보가 라틴보다 많아서,
영어에서 넉넉하게 읽히는 행간이 여기서는 답답하게 읽힌다(W3C klreq · Typotheque). 세 밀도 모두
`--lh-prose ≥ 1.6`을 지킨다.

### 16-1. §3의 함정은 한 층 위에서 다시 나타난다

플레이 화면은 자기 리듬을 **인라인 스타일**로 고정하고 있었다.

```tsx
style={{ '--spacing': '0.25rem' }}   // 인라인은 모든 규칙을 이긴다
```

즉 밀도 설정은 사용자가 40분을 보내는 **바로 그 화면에만 영원히 닿지 못했을** 것이다. 루트 글꼴에서
`style.fontSize`가 놓은 함정과 같은 것이고, 답도 같다 — **JS는 값을 주고 CSS가 계산한다.**

```tsx
<div data-zone="play" …>
```

```css
@layer base {
  [data-zone='play'] {
    --spacing: calc(var(--sp-base) * 0.875);
  }
}
```

상황실은 이제 «0.25rem»이 아니라 «어느 밀도에서든 한 단계 더 조밀»이다.

**이건 브라우저로만 증명된다.** 등록되지 않은 커스텀 속성은 `calc()`를 계산하지 않고 문자열 그대로
계산값이 되므로, `--spacing`을 되읽으면 `calc(var(--sp-base) * .875)`라는 글자가 나온다.
`layout.visual.test.ts`는 그래서 **픽셀을 잰다** — 프로브에 `padding-top: calc(var(--spacing) * 6)`을
주고 해석된 px를 비교한다.

### 16-2. 인쇄는 자기 밀도를 갖는다

조밀한 화면을 고른 사람이 조밀한 인쇄물을 원한 것은 아니다. 종이는 이미 폭이 고정되고 다시 흐른다.
`@media print` 블록이 팔레트를 되돌리는 것과 같은 방식으로 `--sp-base`·`--lh-*`도 되돌린다.

### 16-3. 플레이 화면의 브레이크포인트는 별개 축이다

Tailwind의 단계는 「이 그리드가 아직 들어가나」를 묻고, 플레이 화면의 900/1200은 「두 스크롤 열과
결정 독이 나란히 설 자리가 있나」를 묻는다. 후자의 답은 `lg`와 `xl` 사이 1200에서 갈린다. `xl`에
맞추면 2열 레이아웃이 1280으로 밀려 80px 구간에서 두 열이 들어가는 화면이 1열로 나온다.

폭 보정과 글꼴 보정은 반대로 **같은 수여야 한다.** 1400과 1440으로 40px 어긋나 있어서, 그 사이
구간에서는 틀이 자라고 글자는 자라지 않았다. 둘 다 1440·1800이다.

## 17. 12px은 본문 크기가 아니었다

타입 스케일의 주석은 12px을 «메타데이터용»이라고 적어 두었다. 실제 사용량은 `text-sm` **270회** 대
`text-base` **106회**였다 — 즉 12px 한글이 사람들이 40분씩 읽는 제품의 **사실상 본문 크기**였다.

270개 호출부를 옮기는 대신 **토큰 값을 옮겼다**(`--text-sm: 0.857rem → 0.929rem`, 12px → 13px).
`--border` 값 하나로 166개 테두리를 고친 것과 같은 수법이고, 같은 이유로 안전하다 — 호출부가 변하지
않으면 회귀 표면도 없다.

지금 스케일이 뜻하는 역할:

| 토큰        | 크기(14px 루트) | 역할            |
| ----------- | --------------- | --------------- |
| `text-base` | 14px            | 본문            |
| `text-sm`   | 13px            | 조밀한 본문     |
| `text-xs`   | 11px            | 메타데이터 전용 |

## 18. 한 열의 숫자는 한 스케일

`formatCurrency`는 단위를 **값마다** 고른다. 값 하나가 홀로 있을 때는 맞는 답이고, 두 값이 같은 열에
놓이는 순간 틀린 답이다.

```
3.2조원
8,500억원     ← 축 셋을 쌓아 둔 것이다. 비교하려면 산수를 먼저 해야 한다.
920억원
```

런 도중에도 같다. 현금이 `3.2조원 → 8,500억원 → 920억원`으로 가면 독자는 **단위가 바뀐 것을 먼저
알아차려야** 숫자가 줄었다는 것을 본다. `scaleFor(values, units)`가 스케일을 한 번 고르고 붙잡는다.

| 무엇의 스케일인가      | 무엇으로 정하는가                                      | 어디서                                            |
| ---------------------- | ------------------------------------------------------ | ------------------------------------------------- |
| 지표 하나              | 그 지표의 `metricsHistory` 관측 최대치 (`metricScale`) | 유동성 스트립 · KPI 타일 · 임계 캡션              |
| 표 한 행               | 그 행이 비교하는 값들의 최대치                         | 디브리핑 비교표                                   |
| `before → after` 한 줄 | 두 **끝점**                                            | ImpactPreview · ConsequenceReel · 전 턴 대비 변화 |

마지막 줄이 중요하다. 굴러가는 중의 값에서 스케일을 뽑으면 숫자가 세는 동안 단위가 깜빡인다.

**값과 단위는 두 요소로 그린다**(`<Num>`). 우측 정렬에서 단위 길이가 제각각이면 독자가 열을 훑는
단 하나의 기준점인 소수점이 접미사가 남긴 자리로 흩어진다. 표에서는 단위가 **머리글**에 산다
(`<DataTable>`) — 열이 비교 가능한 축이 되려면 단위는 열의 성질이어야 한다.

통화 기호는 **접두사**다(`$90M`). 단위 전체를 접미사로 다루면 `90$M`이 나온다.
값이 아직 0인 지표는 축이 다른 것이 아니다 — 기본 단위로 떨어뜨리면 `$14.0B` 옆에 `$0.0`이 선다.

## 19. 색은 한 가지 뜻만 갖는다 — 지금 상태

색이 둘을 말하고 있었다. 상태 배지는 `ok|warn|breach`로, 델타는 `better|worse`로 칠해서 한 행에
초록 델타와 빨강 배지가 나란히 설 수 있었다. 게다가 델타의 색은 그 방향을 나르는 **유일한** 채널이라
적록색약(남성 약 8%)에게는 방향 정보가 없었다 — 다른 초록·빨강이 전혀 다른 뜻인 화면에서.

- **색 = 지금 상태.** `dirClass(dir, crossed)`는 `crossed`가 아니면 `text-muted`를 준다.
- **방향 = 모양 + 낱말.** `formatDelta`의 `▲`/`▼`와 `DIR_TEXT`의 개선/악화. `sr-only`에 두지 않는다 —
  색이 사라져도 뜻이 남아야 하는 것이 요점이다.
- **예외는 하나**: 임계 밴드를 넘은 변화. 눈이 가야 할 바로 그 순간이고, 아껴야 끌어당김이 작동한다.

`Record<Direction, string>` 지도를 다시 만들지 않는다. 거기엔 «넘었는가»를 넣을 자리가 없어서,
지도가 있는 한 부호만으로 칠하는 코드가 다시 생긴다.

**알약 예산.** 채워진 배지는 «뭔가 잘못됐다»는 뜻이다. 크롬 라벨(채널 태그·힌트 단계·소요 시간·
모드)은 `label-caps` 텍스트다. 와이어 항목 메타 줄에 알약 넷이 서 있으면 어느 것도 눈을 끌지 않는다.
`통상`처럼 평상 상태를 말하는 배지는 그리지 않는다.

## 20. 펼치기 어휘는 셋이고, 뜻이 다르다

| 형태             | 뜻                        | 예                                              |
| ---------------- | ------------------------- | ----------------------------------------------- |
| `자세히 ⇄ 접기`  | 숨어 있는 **상세**        | 선택지 전체 설명, 지식 카드                     |
| `더 보기 ⇄ 접기` | **잘린** 내용             | 잘린 문단, 상한 걸린 목록                       |
| `… →`            | **이동** — 닫을 것이 없다 | `자세히 →` · `전체 지표 →` · `피드 전체 보기 →` |

이름이 있는 절(`배경`·`근거 보기`·`표로 보기`)은 이름을 지킨다. 무엇이 열리는지 말하는 편이 동사보다
많이 말하고, 셋 다 `aria-expanded`를 가진 진짜 디스클로저다.

한때 플레이 화면 하나에 아홉 가지가 있었다. 낱낱은 다 읽히지만, 모이면 독자가 **누르기 전에 무엇이
일어날지 배우는 일** 자체를 막는다 — 관례의 존재 이유가 그것이다.

## 21. 기본 펼침은 과제를 밀어낼 수 있다

안내 모드 첫 턴에서 결정 독의 스크롤 높이가 **3,672px**인데 첫 선택지가 **y=3,043**에 있었다.
712px 열이므로 **6개 선택지 중 0개가 화면에 없었다.** 원인은 «먼저 읽게 한다»는 옳은 의도로 지식
카드를 기본 펼침으로 둔 것이고, 비용이 2,813px이었다.

**넛지의 비용을 재라.** 한 줄짜리 리드는 스크롤로 지나치는 벽보다 나은 넛지다. `InlineCard`의 `lead`
이후: 1,239px · 첫 선택지 610px · 보이는 선택지 3개.

그리고 요약은 제목이 아니다. `firstSentence`는 선행 마크다운 제목을 건너뛴다 — `## 정의`로 시작하는
카드가 자기를 「정의」라는 한 낱말로 요약하고 있었다.

## 22. 저작해 둔 것은 보여 준다

디브리핑에서 가장 크게 빠져 있던 것은 없는 정보가 아니라 **있는데 오지 않은 정보**였다:
`Option.feasibility`(출처 포함) · `Option.calibrationNote` · `DimensionScore.explanation[]`(호버
툴팁에만) · `DecisionRecord.elapsedMs`(줄곧 기록, 표시 0회) · 지표 추이(최종값만 있었다).

그리고 **못 한다고 적어 둔 이유가 사실인지 확인한다.** `largestExpertGap`의 주석은 방향을 말할 수
없는 이유로 「`KpiSpec`에 방향이 없다」고 적었다. 맞는 말이지만 `Threshold.direction`에는 있고,
`directionOf`가 플레이 화면에서 줄곧 그걸 읽고 있었다. 지금은 임계값이 있으면 말하고 없으면 침묵한다.

**기계 이름은 화면에 오지 않는다.** 라벨 없는 경로는 **감춘다** — 라벨 없는 숫자는 정보가 아니고,
무엇을 재는지 잘못 짚은 독자는 못 본 독자보다 나쁘다.

## 23. 근거는 저작된 것만 말한다 — 기본값으로 지어내지 않는다

`ThresholdBand`에 한때 이런 기본값이 있었다: `basis`가 없으면 「훈련 경고선」.

그런데 이 저장소의 threshold 중 `basis`를 저작한 것은 **하나도 없다**(시나리오 13개의
`thresholds` 블록 60여 개, `metrics/thresholds.ts`의 기본값 25개 모두 `{warn, breach, direction}`
뿐이다). 그래서 그 «기본값»은 사실상 유일한 값이었고, 규제로 정해진 선까지 전부 훈련용이라고
화면이 단언했다 — NCR 100%(경영개선권고 발동선), CET1 8%, LCR 100%. 그 옆에서 같은 타일이
저작된 `referenceLabel`로 「권고 100%」·「내부 기준 100%」·「사후 규제 기준: …」을 적고 있었다.
한 화면이 같은 숫자를 두고 서로 다른 말을 했다.

§22가 「라벨 없는 경로는 감춘다」로 끝나는 것과 같은 규칙이다. **모르는 것을 잘못 말하는 것은
아무 말도 하지 않는 것보다 나쁘다.** 근거 문구는 `basis`가 실제로 저작됐을 때만 나타난다.
`Threshold.asOf`·`sourceRefs`도 같은 취급 — 타입은 저작 경로를 열어 두기 위해 남기고, 값이 없으면
줄 자체가 없다.

`tests/ui/thresholdBasis.test.tsx`가 양방향으로 잠근다: 저작하지 않으면 캡션에도 접근명에도 근거
낱말이 없을 것, 저작하면 그 낱말이 나올 것.
