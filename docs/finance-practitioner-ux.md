# 금융 실무자 개인 훈련: UI/UX 검토와 적용

대상은 은행·증권·운용·정책 실무자의 개인 훈련이다. 기존의 결정 → 결과 → 복기 구조를 유지하면서, 자금의 가용 시점과 판단 근거를 읽기 쉽게 만드는 데 우선순위를 둔다.

## 프로젝트 이해와 확인된 문제

React 화면과 순수 결정론적 시뮬레이션 엔진이 분리되어 있다. 13개 시나리오는 은행, 증권사, 연기금, 프라임브로커, 자산운용, 정책당국의 상태를 사용한다. 저장 데이터는 결정 로그를 재생해 상태를 복원한다. 기존 역할별 지표, 도움말, 영향 프리뷰, 대화, 실행 취소, 점수·경로 비교를 확장했다.

검토에서 재현한 오류:

- 저장 스키마가 대화 `path`를 제거해, 완료된 약속·대화의 효과가 복원 때 사라졌다.
- 결정별 힌트 감점이 재생되지 않아 복원 전후 점수가 달랐다.
- 완료 기록과 분기 재시작에서 변동성이 누락될 수 있었다.
- 은행의 시나리오 전체 누적 유출과 향후 1일 예상 유출을 ‘오늘 누적/예상’으로 묶었다.
- 구간마다 초기화되는 유출률을 이전 구간과 비교해 개선으로 표시했다.
- 안내 모드와 타이머 비활성 설정에서도 돌발 대응의 응답 제한이 작동했다.
- 조기 종료한 플레이어와 더 오래 진행한 전문가 경로의 최종값을 비교했다.
- 전문가 모드에서도 미래 사건을 설명하는 학습 자료를 열 수 있었다.

| P1       | 전문가 모드의 사전 선택 해설·미래 학습 자료·출처 및 용어 링크를 종료 후로 미룸                     | 도움 시트에서도 현재 지표의 산식·기간·기준 설명만 제공         |
| P2       | 동일 seed·변동성과 같은 시점의 KPI 비교를 기본으로 제공, 각 경로 최종값 비교 전환                  | 먼저 종료된 경로의 값을 이후 시점으로 이월하지 않음            |
| P2       | 비교 조건과 판단 기록을 텍스트 복사에 포함                                                         | 공유한 결과의 비교 시점을 알 수 있음                           |
| P2       | 개념 카드의 마크다운 제목 대신 본문 소개 표시, 모바일 시작 버튼 줄바꿈 방지, 결정 탭에도 마감 표시 | 좁은 화면에서도 핵심 지표와 다음 요청을 확인                   |

경고선은 별도 근거가 없는 경우 ‘훈련 경고선’으로 표시한다. `Threshold.basis`, `asOf`, `sourceRefs`로 규제 기준·내부 한도·기준일·출처를 구별할 수 있다. 기존 수치를 최신 법규상 한도로 재분류하지 않았다.

## SVB 자금 일정표 후속 적용

SVB 오전·오후 구간에 현재 조건을 유지한 시간별 지급·잔고 추정, 첫 부족 예상 시점, 미인출 한도와 금요일 장전 반영 예정 담보를 추가했다. 목요일 마감 기록은 야간 조달 후 현재 잔고와 분리한다. 시간 배분은 훈련 가정이며, 확정 송금 원장을 확보한 것은 아니다. 상세 근거·계산 범위·검증은 [SVB 결제·자금 일정표](./svb-funding-schedule.md)를 참조한다.

## SVB 정보 공개 시점 후속 적용

SVB 35개 이벤트에 공개 가능 시각을 저술하고, 현재 시각보다 늦은 보고를 숨긴다. BTFP 공개의 EDT 오프셋을 바로잡고 일요일 내부 보고가 모두 도착한 21:00 ET를 브리핑 시각으로 사용한다. 금요일·월요일 이후의 확정 사실이 앞서 노출되던 본문은 내부 점검·모의 스트레스로 재구성했다. 전문가 해설의 설정 우회와 영향 화살표도 차단했으며, 이전 구간·저장 복원에서 늦게 도착한 보고를 다시 읽을 수 있다. 브라우저 검토에서 발견한 모바일 상단 KPI 말줄임도 수정해 금액·생존 일수 전체를 표시한다. 검토 범위와 한계는 [SVB 정보 공개 시점 검토](./svb-information-release.md)를 참조한다.

## 레고랜드·LDI 자금 실행 관점 후속 적용

직접 금융 실무자의 의사결정 순서를 따라 검토했다. 증권사의 미처리 만기 묶음을 30일 만기로 표시하던 오류를 고치고, 현금·미인출 은행 약정·첫 만기 자체매입 추정을 분리했다. LDI는 스킴 현금과 풀 내부 현금·적격 담보를 구분하고 기관별 유동자산 산식을 바로잡았다. 후속 처리에는 선택한 지시와 시나리오상 날짜·시각을 표시한다. 발견 근거, 적용 내용, 우선순위별 후속 계획은 [금융 전문가 직접 검토](./financial-expert-review.md)를 참조한다.

## 금융 콘텐츠를 보강할 다음 단계

현재 모델에 없는 결제 원장을 UI가 만들어 내지는 않는다. 아래 항목은 SVB·레고랜드·LDI부터 출처와 가정을 명시해 저술한 뒤 확장한다.

1. **지급 일정**: 금액, 통화, 확정/추정, 결제 마감, 현금화 가능 시각, 선후관계. 시간대별 현금 부족액은 이 정보가 갖춰진 후 계산한다. 1일 예상 유출과 30일 LCR을 당일 결제 부족액으로 대체하지 않는다.
2. **실행 조건**: 조달 금액, 담보 자격·평가·헤어컷, 기존 담보 중복 사용 여부, 승인 주체, 인출·결제 시간, 비용과 손실, 실패 조건. 지금은 선택지에 명시된 설명과 실행 가능성 근거까지만 비교한다.
3. **약속 이행**: 대화 경로에 저장된 약속을 별도의 약속·승인·담보 이전 원장으로 표시하려면 시나리오별 카운터와 그 의미를 저술해야 한다. 후속 처리 대기열을 확정된 입금 일정으로 취급하지 않는다.
4. **정보 공개 시점**: SVB의 이벤트·결정·대화를 검토하고 공개 시각 검증을 적용했다. 나머지 시나리오에도 시각·출처·재구성 여부를 저술해야 한다. 제목에서 사건 자체를 이미 아는 한계와, 명칭 검사만으로 모든 미래 사실을 찾을 수 없는 한계가 남는다.
5. **복기**: 기존 점수와 추천 체계를 유지한다. 실제 업무 역량 인증, 선택과 결과 사이의 정량적 인과 분해, 판단 메모 자동 채점은 검증 없이 추가하지 않는다. 다음 훈련 연결은 기존 약점 추천·재시작 기능을 활용한다.

과거 버전에서 이미 제거되어 저장된 대화 경로는 복원할 근거가 없다. 새 저장분은 경로를 보존하며, 구형 힌트 기록은 당시 모드와 사용 단계로 복원한다.

## 검증과 금융 전문가 직접 검토 방식

자동 검증은 엔진·저장·화면 회귀 테스트, TypeScript, ESLint, 프로덕션 빌드로 수행한다. 브라우저 검토 대상은 데스크톱과 390px 모바일의 브리핑·상황실·대안 비교·디브리핑이다. 금융적 의미는 코드·시나리오·출처와 화면을 직접 대조해 판단하고, 자동 점검은 계산·저장·표시 오류를 확인하는 데 사용한다.

최초 UI/UX 개선 단계의 검증 결과(후속 SVB 단계는 각 문서 참조):

- 전체 테스트: 1,287개 통과, 기존 건너뛰기 8개. 저장·복원, 응답 시간 제어, 대안 비교, 전문가 자료 제한 회귀 테스트 포함.
- TypeScript 검사, ESLint, 프로덕션 빌드 통과. 기존 500kB 초과 번들 경고는 남아 있다.
- Chromium 브라우저: SVB 브리핑·전문가 브리핑·상황실·대안 비교·대시보드·390px 모바일 결정 화면·두 비교 기준 모두 가로 넘침 없음.
- 긴 대안 비교에서 화면 밖 빈 영역으로 이어지던 세로 스크롤을 수정했다. 결정 열은 내부에서 스크롤하고 바깥 문서 높이는 뷰포트를 유지한다.
- LDI 변동성 1 / seed 3 완료 기록을 실제 새로고침 후 복원: 55.0점 유지. 저장 기록에서 분기 재시작한 상태의 변동성 1 유지. 브라우저 페이지 오류 없음.

개선 담당자가 은행 자금부·증권사 자금/리스크·연기금 CIO·정책당국의 판단 흐름을 따라 직접 검토하고 수정한다. 외부 참가자 모집이나 평가를 후속 구현의 선행 조건으로 두지 않는다. 다음 항목별로 문제를 재현하고 금융적 영향·구현·검증 근거를 기록한다.

- 지금 사용할 현금, 미인출 약정, 담보, 후속 처리 예정액이 분리되는지 확인한다.
- 다음 지급·결정 마감과 모델에 없는 결제 정보를 구별한다.
- 대안의 권한·승인·담보·결제 조건을 판단 전에 확인할 수 있는지 점검한다.
- 현재 시점에 알 수 있는 사실만으로 결정할 수 있는지 본문·선택지·도움말을 검토한다.
- 동일 시점의 복기 비교와 저장 복원이 기존 판단 근거를 보존하는지 확인한다.

## 검토 근거

- [BIS: Monitoring tools for intraday liquidity management](https://www.bis.org/publications/201304-standards-monitoring-tools-intraday-liquidity-management): 일중 유동성의 모니터링 목적을 바탕으로 결제 시점의 자금 여력과 LCR을 구별한다.
- [World Bank: A Guide to Financial Sector Crisis Simulation Exercises](https://documents.worldbank.org/en/publication/documents-reports/documentdetail/099125002162330340): 역할·판단·복기의 훈련 구조 참고.
- [W3C: Timing Adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html): 시간 제한을 끄거나 조정하는 사용자 통제 참고. 이 변경만으로 WCAG 전체 준수를 주장하지 않는다.
