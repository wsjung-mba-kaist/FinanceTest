# 시나리오 저작 가이드 (Scenario Authoring Guide)

이 문서는 금융위기 대응 시뮬레이션의 시나리오를 저작(authoring)하는 사람을 위한 규칙서다. 저작 파이프라인, 저자 체크리스트, 파일 구성, 무결성 린트, 보정 규칙, 스펙 템플릿, 옵션·디브리핑 작성 규칙, 시나리오 카탈로그를 담는다. 여기의 수치는 구현 계획(plan)에서 확정된 값이며, 엔진(`src/engine/fx/bank.ts`, `src/metrics/runoff.ts`)의 기본값이자 시나리오가 오버라이드할 수 있는 기준값이다.

워크드 예제(worked example)는 `docs/scenarios/svb-2023.md`를 참조한다.

---

## 1. 목적과 원칙

### 1.1 정확성 최우선 (accuracy first)
모든 수치·사건은 공신력 있는 출처(중앙은행·감독당국 사후평가, 공시, 학술자료)로 추적 가능해야 한다. 초기 대차대조표의 숫자 하나, 턴에 등장하는 금리 하나까지 출처 ID와 기준 시점(as-of)을 가진다. 언론 보도는 사건의 타임스탬프와 인용문에만 쓰고, 언론 단독 보도의 대차대조표 수치는 사용하지 않는다. 확인되지 않은 값은 `[VERIFY]` 태그로 남기되, 릴리스 시점에는 0건이어야 한다.

### 1.2 합성 기관 + 실제 외생 사건 (synthetic institution, real exogenous events)
플레이어가 맡는 기관은 실명 대신 **보정된 합성 기관**(예: SVB → "Pacific Valley Bank")을 사용한다. 합성 기관의 대차대조표는 실제 공시를 반올림·양식화한 것이며, 실제와의 차이는 대조표와 디브리핑에 명시한다. 반면 외생 사건·시장 데이터·정책 대응(금리, 지수, 스프레드, 강등, 당국 발표)은 실제 기록을 그대로 사용한다. 이 분리 덕분에 플레이어의 결정이 기관 상태를 바꾸어도 바깥 세계의 시계열은 불변으로 유지된다.

### 1.3 사후정보 금지 (no hindsight)
플레이어에게 보이는 모든 정보 항목은 `knownAt` ≤ 턴 시각이어야 한다. 내부 수치(자기 기관의 잔고·대기열)는 실시간으로 알 수 있지만, 외부 정보(경쟁사 실패, 당국 발표, 등급 조치)는 실제 공표 시각 이후에만 노출한다. 턴별 금지 토큰을 두어 미래 용어의 누출을 린트로 잡는다(예: 2023-03-12 18:15 ET 이전에는 "BTFP"라는 단어가 등장할 수 없다). 플레이테스트 게이트 중 하나가 "사후정보 누출 0"이다.

### 1.4 결정론 (determinism)
시나리오는 순수 데이터(TS 모듈), 엔진은 순수 함수 리듀서다. 시계·`Math.random`·`Date.now()`를 쓰지 않는다. 저장은 `seed + decisions[]`만이며, 복원·되감기·what-if·경로 비교는 모두 `replay()`로 이루어진다. 확률적으로 보이는 결과(증자 성공 여부, 등급 반응, 감독당국 개입)는 모두 **상태 임계값**으로 인코딩한다(예: 증자 성공 조건 = 백스톱 100% 또는 (CI ≥ 45 ∧ 백스톱 ≥ 50%)). 동일 seed와 동일 결정 로그는 항상 동일 결과를 낸다.

## 2. 저작 파이프라인 11단계

| 단계 | 산출물 | 게이트 |
|---|---|---|
| ① 도시에 수집 | `sources.ts` (S1..Sn: 유형·일자·URL·페이지) | 출처 ≥1 primary/regulatory; 언론은 타임스탬프·인용에만 |
| ② 사실 원장 | `facts.ts` (값·단위·as-of·`knownAt`·가시성·출처ID·태그) | 릴리스 시 [VERIFY] 0건 |
| ③ 타임라인·정보 컷 | `timeline.ts` + 정보 컷 표 | 타임존 명시; 가시성 public / role-internal / regulator-only |
| ④ 역할·기관 프로필 | 양식화 대차대조표 + 출처→게임값 대조표 | A = L + E; 재계산 CET1 ±0.5pp |
| ⑤ 결정 맵 | 턴 × 결정 × 3~5옵션 | 옵션별 실행가능성 근거; 역사 옵션 표시; 함정 ≥1 |
| ⑥ 보정 시트 | `calibration.md` | 효과별 산식·앵커·크기 기록 |
| ⑦ 스펙 | `docs/scenarios/<id>.md` (8섹션) | 금융 SME 정확성 리뷰 + 교육 리뷰 |
| ⑧ 데이터 파일 | TS 모듈 (`scenario.ts` 외) | `pnpm typecheck` 통과 |
| ⑨ 검증 | 린트 결과·역사경로 재현·경로 열거 | 무결성 이슈 0건; 체크포인트 ±15%; 게임오버 도달 가능 |
| ⑩ 플레이테스트 | 플레이테스트 기록 | 현실감 ≥4/5; 퀴즈 사전/사후 ≥+2/5; 사후정보 누출 0 |
| ⑪ 사인오프 | semver 버전, 변경로그, 출처 동결 | 리뷰어 승인 |

### ① 도시에(dossier) 수집 → `sources.ts`
시나리오의 근거가 되는 1차 자료를 먼저 모은다: 감독당국 사후평가, 공시(10-K, 8-K, 콜리포트), 중앙은행 리뷰, 학술 논문, 통계 시계열. 각 출처에 `S1..Sn` ID를 부여하고 유형·일자·URL·페이지를 기록한다. 언론 기사는 사건의 타임스탬프와 당사자 인용을 잡는 용도로만 등록하고, 수치의 근거로 쓰지 않는다. 이 단계의 결과는 `docs/research/<id>.md`에 서술형 도시에로도 남긴다.

### ② 사실 원장(FactLedger) → `facts.ts`
초기 상태와 턴 이벤트에 들어갈 모든 숫자를 원장 항목으로 등록한다. 항목마다 값·단위·기준 시점(as-of)·역할이 알게 되는 시각(`knownAt`)·출처 ID·태그를 적는다. 출처로 확인되지 않은 값은 `VERIFY`, 의도적으로 단순화한 값은 `STYLIZED`, 보정 규칙에서 도출한 값은 `CAL`로 태그한다. 릴리스 게이트는 `VERIFY` 0건이다 — 1차 출처로 해소하거나 `STYLIZED`로 바꾸고 디브리핑 '단순화 노트'에 명시한다.

### ③ 타임라인·정보 컷 → `timeline.ts`
역할 간 공유되는 외생 시계열(금리·지수·CP·스프레드·주가)을 턴 단위로 한 번만 정의한다. 일 단위 턴은 일별, 일중 턴은 일중 값을 쓰며 타임존(PT, ET, KST 등)을 명시한다. 정보 항목마다 가시성을 public / role-internal / regulator-only로 분류하여, 같은 사건이라도 역할에 따라 언제 무엇을 볼 수 있는지 정보 컷 표를 만든다. 정책담당 역할 변형은 이 타임라인을 재사용한다.

### ④ 역할·기관 프로필
합성 기관의 양식화 대차대조표를 만들고, 출처 값 → 게임 값 대조표를 함께 작성한다. 자산 = 부채 + 자본이 맞아야 하며, 대조표의 값으로 CET1을 재계산했을 때 실제 공시와 ±0.5pp 이내여야 한다. 역할의 권한 한계(무엇을 결정할 수 있고 무엇은 CEO/이사회/당국 소관인지)를 명문화하고, 사용 불가 행동(인출 정지, 미존재 창구)을 열거한다. 예금·조달을 세그먼트로 나누고 각 세그먼트의 규모와 유출 특성을 기록한다.

### ⑤ 결정 맵
턴 × 결정 × 옵션의 격자를 만든다. 결정은 턴당 1~3개, 옵션은 결정당 3~5개다. 옵션마다 당시 실재한 창구·합법성·턴 내 운영 가능성을 근거로 실행가능성을 적고, 실제로 선택된 옵션에 역사 표시(historical)를 한다. 시나리오마다 매력적으로 보이지만 역사적으로 틀린 함정 옵션을 1개 이상 둔다. 이 단계에서 학습목표(LO)와 결정을 매핑하여 각 LO가 2개 이상 결정에서 연습되는지 확인한다.

### ⑥ 보정 시트 → `calibration.md`
옵션 효과와 이벤트 효과의 크기를 하나씩 정당화한다. 효과별로 산식·앵커(역사적 유사사례 또는 문서화된 규칙)·크기를 표로 남긴다. 이 문서의 6절 보정 규칙 기본값을 그대로 쓰면 "기본값 사용"으로, 오버라이드하면 그 근거를 적는다. 역사 경로 재현 검증(체크포인트 산식)도 여기에 기록한다.

### ⑦ 스펙 → `docs/scenarios/<id>.md`
7절의 8섹션 템플릿으로 사람이 읽는 스펙을 완성한다. 금융 SME(subject-matter expert)가 정확성을, 교육 담당자가 학습 설계를 리뷰한다. 리뷰 코멘트는 스펙에 '리뷰 노트'로 남기고 해소한다. 이 스펙이 ⑧ 데이터 파일의 유일한 원본이다.

### ⑧ 데이터 파일(TS 모듈)
스펙을 `src/scenarios/<id>/` 아래 TS 모듈로 옮긴다. `defineScenario<State>({...})`로 타입 검증을 받고, 논리가 필요한 효과는 `src/engine/fx/*`의 이름 있는 효과 빌더를 재사용한다. 스펙과 코드가 어긋나면 스펙을 고친 뒤 코드를 고친다.

### ⑨ 검증
`pnpm test`로 무결성 린트(5절)와 오토플레이어를 돌린다. 역사 경로가 체크포인트 ±15%로 재현되는지, 전문가 경로 점수가 역사 경로 이상인지, 게임오버가 BFS 경로 열거로 도달 가능한지 확인한다. DevScenarioInspector에서 이슈 0건을 눈으로 확인한다.

### ⑩ 플레이테스트
역할 경험이 있는 테스터 3명 이상이 플레이한다. 게이트는 현실감 ≥4/5, 퀴즈 사전/사후 향상 ≥+2/5, 사후정보 누출 0건이다. 테스터가 "이 시점에 이걸 알 수 없었다"고 지적한 항목은 `knownAt`을 재검토한다.

### ⑪ 사인오프
`scenarioVersion`을 semver로 올리고 변경로그를 쓴다. 출처 목록을 동결하여 이후 수정은 새 버전으로만 이루어지게 한다. 버전 불일치 시 진행 중인 런은 폐기 안내되므로, 저장 호환성에 영향이 있는 변경은 major를 올린다.

## 3. 저자 체크리스트 (14항목)

1. **초기값 전부 출처 + as-of.** — 왜: 대차대조표 숫자 하나가 틀리면 파생지표(LCR, CET1, TCE)가 연쇄적으로 틀린다.
2. **외생 시계열은 일별(일중 턴은 일중) 출처.** — 왜: 턴 단위보다 거친 데이터는 결정 시점의 시장 상황을 왜곡한다.
3. **언론 단독 대차대조표 수치 금지.** — 왜: 언론 수치는 오기·추정이 섞여 있고 사후 정정되는 경우가 많다.
4. **모든 정보 항목 `knownAt` ≤ 턴 시각(내부 수치는 실시간, 외부는 공표 후).** — 왜: 사후정보가 섞이면 훈련이 아니라 정답 맞히기가 된다.
5. **옵션 효과 크기는 (a) 역사적 유사사례, (b) 문서화된 규칙(Basel 유출률·PCA·연준/FHLB 헤어컷·ASC 320 tainting·8-K 시한), (c) [CAL] 노트 + 앵커 중 하나로 정당화.** — 왜: 근거 없는 효과 크기는 게임을 저자의 직관으로 만든다.
6. **옵션별 실행가능성(당시 존재한 창구·합법·턴 내 운영 가능).** — 왜: 당시 없던 창구를 쓰는 옵션은 잘못된 교훈을 남긴다.
7. **역사 경로는 체크포인트(일별 유출·폐쇄 시점·손실) ±15% 재현.** — 왜: 역사를 재현하지 못하는 보정은 다른 경로의 결과도 신뢰할 수 없다.
8. **전문가 경로는 결과 + 생존 불확실성 캐비앳 명시.** — 왜: "최선을 다해도 실패할 수 있었다"는 사실 자체가 교훈이다.
9. **expert rating은 공식 사후평가 인용(<20 또는 >80은 1차 사후평가 또는 2개 출처).** — 왜: 극단적 평점은 점수에 큰 영향을 주므로 더 강한 근거가 필요하다.
10. **함정 옵션 ≥1.** — 왜: 매력적이지만 틀린 선택을 경험하는 것이 시뮬레이션 훈련의 핵심 가치다.
11. **학습목표 3~5개, 각각 ≥2 결정에서 연습.** — 왜: 한 번의 결정으로는 역량이 형성되지 않는다.
12. **디브리핑(역사 결과·전문가 경로·인용 교훈·퀴즈 5).** — 왜: 구조화된 디브리핑 없는 훈련은 효과가 검증되지 않는다(World Bank CSE 설계 원칙).
13. **게임오버 조건 도달 가능 + 게임 내 규칙 표시.** — 왜: 도달 불가능한 게임오버는 긴장감을 없애고, 규칙이 숨겨지면 실패가 학습으로 이어지지 않는다.
14. **결정론만(확률은 상태 임계값으로 인코딩).** — 왜: 되감기·리플레이·경로 비교가 모두 결정론에 의존한다.

## 4. 파일 구성

### 4.1 시나리오 폴더 `src/scenarios/<id>/`

| 파일 | 내용 |
|---|---|
| `scenario.ts` | `defineScenario<State>({...})` 진입점. meta(id, 제목, 역할, `durationTurns`, `scenarioVersion`), `initialState`·`turns`·`scoring`·`debrief`·`sources` 조립, `paths.historical` / `paths.expert`(옵션 ID 시퀀스 + 체크포인트), `gameOverRules[]`(선언적: `{metric, lt}`, `{flag}`, `consecutiveTurns`). |
| `initialState.ts` | 기관 상태(`institution.kind`별 discriminated union: bank / pension / securities / prime_broker / central_bank / asset_manager) + `MarketState` + `ConfidenceState`(depositors, counterparties, regulators, investors, media, board: 0..100) + 초기 `flags`·`counters`. 모든 숫자 리프는 `facts.ts`의 경로와 1:1 대응해야 한다. |
| `turns.ts` | `Turn[]`. 턴마다 `id, label, timeLabel, entryEffects?(외생 충격), events[](newswire / memo / regulator_call / market_update / dialogue / data_release; `when?`, `effects?`, `cardRefs?`, `sourceRefs?`, `reliability?`), decisions[](1~3), advisorHints?`. 결정마다 `prompt, context, when?, required?, select?{min,max}, timeLimitSec?, defaultOptionId?, options[], tags?`. |
| `scoring.ts` | 역할별 7차원 가중치(liquidity · solvency · marketRisk · communication · compliance · policy · timeliness, 합 100)와 `ScoreComponent[]`(metric aggregate + piecewise-linear curve / counter / expert / flag / adjust), `failureCap`(기본 40). |
| `debrief.ts` | 역사 결과 서사, 전문가 경로 서사와 생존 캐비앳, 교훈(각 `sourceRefs` ≥1), 퀴즈 5문항(해설 `sourceRefs` ≥1), 단순화 노트, 실패 분기 반성 프롬프트. |
| `sources.ts` | `S1..Sn` 서지: 유형(primary / regulatory / academic / data / press), 일자, URL, 페이지. 최소 1개 primary 또는 regulatory. 공유 서지 `src/content/sources.ts`를 참조할 수도 있다. |
| `facts.ts` | `FactLedger[]` (아래 4.2). |
| `timeline.ts` | 역할 간 공유 외생 시계열(정책금리, 국채 2y/10y/30y, 신용스프레드, 펀딩 스트레스, 지수, 변동성, 환율, 섹터 주가). 정책담당 변형 역할이 재사용. |
| `calibration.md` | 보정 시트: 효과별 산식·앵커·크기, 기본값 오버라이드 근거, 역사 경로 재현 산식. |

### 4.2 FactLedger 형태

```ts
type FactLedger = {
  path: string;            // initialState 또는 timeline 내 경로 (예: 'institution.deposits.corporateUninsured')
  value: number;
  unit: string;            // 'USD_B', 'bp', 'pct', 'count' ...
  asOf: string;            // 값의 기준 시점 (ISO 8601, 타임존 포함)
  knownAt?: string;        // 역할이 이 값을 알게 되는 시각; 생략 시 asOf와 동일
  sourceId: string;        // sources.ts의 S-id (예: 'S1')
  tag?: 'VERIFY' | 'STYLIZED' | 'CAL';
};
```

가시성(public / role-internal / regulator-only)은 타임라인·정보 컷(③)과 이벤트에 기록하며, 사실 원장에서는 `knownAt`으로 역할 기준 인지 시점을 표현한다.

**태그 범례**

| 태그 | 의미 | 저자가 할 일 |
|---|---|---|
| (없음) | 1차 출처로 확인된 값 | `sourceId`·`asOf` 정확히 기재 |
| `VERIFY` | 아직 1차 출처로 확인되지 않은 값(조사 도시에의 [UNVERIFIED] 항목) | 릴리스 전 1차 출처로 해소하거나 `STYLIZED`로 전환 + 단순화 노트. 릴리스 시 0건 |
| `STYLIZED` | 실제와 의도적으로 다르게 반올림·단순화한 값(예: 합성 기관 현금 12[STYLIZED]) | 실제 값과 차이를 대조표·디브리핑 단순화 노트에 명시 |
| `CAL` | 출처가 아니라 보정 규칙·앵커에서 도출한 값(유출률, 효과 크기, 희석률 등) | `calibration.md`에 산식·앵커 기록 |

### 4.3 문서

|---|---|
| `docs/research/<id>.md` | 조사 도시에. 검증된 수치와 출처, [UNVERIFIED] 목록, 교훈 출처, 시계열 데이터 소스. `facts.ts`의 `VERIFY` 항목과 대조하는 원본. |

## 6. 보정 규칙 (Calibration Rules)

엔진 기본값이며 시나리오가 `calibration.md`에 근거를 적고 오버라이드할 수 있다.

### 6.1 신뢰지수 CI (Confidence Index, 0~100)

```
CI_t = clamp(CI_{t-1} + ΣΔCI_events + 0.4 × 자사주가수익률%)
```

**ΔCI 이벤트표**

| 이벤트 | ΔCI | 앵커 |
|---|---|---|
| 손실 공개 + 미백스톱 증자 | −25 | SVB 3/8→9 |
| 완전 백스톱 증자 | −5 | CS 2022.10 |
| 1노치 강등 | −5 | |
| 다노치 / 정크 강등 | −15 | |
| 증자 실패·철회 | −25 | |
| 가시적 유출 >10%/일 | −15 | |
| 동종 피어 실패 | −5 | |
| 감독당국 확인 유동성 ≥ 무보험의 50% | +10 | FRC 3/12 |
| 컨소시엄 예금 | +10 | |
| 전면 보증 | +40 | |
| 지급 지연 가시화 | −20 | 시그니처 |
| 수치 없는 CEO "침착" 콜 | −3 | |

### 6.2 런 상태 (Run State) S0~S3

| 상태 | 이름 | CI 범위 |
|---|---|---|
| S0 | 평온 | ≥70 |

| S2 | 공개 런 | 30~49 |

### 6.3 예금 유출 (Deposit Outflow)

```
Outflow = Bal × min(cap, r_base(seg, state) × Π증폭 × Π완화)
```

일중 턴은 송금 창구 시간에 비례하여 배분한다.

### 6.6 시장 충격 처리(기관 역할)

- 외생 일별 시계열은 `timeline.ts`에 1회 정의한다. 플레이어는 익스포저만 변경한다: `P&L = Σ exposure × Δprice`.
- 파이어세일 할인은 자기 체결가에만 적용한다(시계열 불변).
- 자사 주가(반사실 경로) = 섹터 수익률 + 결정론적 이벤트 반응:

| 이벤트 | 자사 주가 반응 |
|---|---|
| 손실 + 미백스톱 증자 | −45~−60% |
| 실패 | −50~−65% + 거래정지 |
| 완전 백스톱 | −10~−20% |
| 피어 전이 | −15~−35% |
| 피어만 보증 | 0~−10% |

### 6.7 정책 탄력성(감독·중앙은행 역할)

정책 = 발표 효과(당일, 범위 내 상품) + 집행 효과(주간) + 스필오버(범위 외, 소폭·지연).

| 범위 일치 | 발표 효과 |
|---|---|
| full | 100% |
| partial | 40% |
| none | 10% |

**앵커**

| 사례 | 관측 |
|---|---|
| BoE 2022.9.28 | 30년 −100bp+, 종료 신호 시 변동성 복귀 |
| 미국 2023.3.12 SRE+BTFP | 커버 은행 유출 ×0.1, 유사 인식 ×0.5, KRE −12% 반등 없음 |
| 한국 2022.10.23 50조+α | 채안펀드 적격 회사채 부분 회복; PF-ABCP A2·증권사 CP는 상품 특정 프로그램(11/11, 11/24)까지 3~5주 상승 지속 |

### 6.8 등급 반응(결정론)

검토 트리거(하나라도 해당 시): 실현손실 > TCE 10% · 증자 실패 · 유출 > 5%/주 · CI < 50

| CI | 조치 |
|---|---|
| ≥50 | 1노치 |
| 30~49 | 2노치 |
| <30 또는 정리 | 정크·철회 |

CDS 프록시: CI→CDS 매핑표(CS 5y 250bp 2022.9 → >1,000bp 2023.3.15). 역전 또는 >1,000bp 시 무담보 라인 차단.

## 8. 옵션 작성 규칙

| 항목 | 규칙 |
|---|---|
| `label` | 동사로 시작(verb-first), 12어절(words) 이하. 예: "AFS $21B 일괄 매각하고 $2.25B 증자 발표" |
| `description` | 무엇을, 어떤 창구로, 얼마나 — 실행가능성 근거 포함(당시 존재한 창구·합법·턴 내 운영 가능) |
| `effects[]` | 즉시 효과. `op`(path·op·value) / `flag` / `counter` / `confidence` / `fn`(이름 있는 효과 빌더). 효과마다 `calibration.md`의 cal 노트 참조(산식·앵커) |
| `delayedEffects[]` | `{afterTurns, when?, effects, description}` — 턴 오프셋 명시. 프리뷰에는 설명 텍스트만 노출(미래를 보여주지 않음) |
| `expert.rating` | 0~100. 공식 사후평가 인용; <20 또는 >80은 1차 사후평가 1개 또는 출처 2개 |
| `expert.rationale` | 왜 이 평점인지 + `sourceRefs`. `historicalNote?`에 실제로 일어난 일 |
| `historical` | 실제 선택된 옵션에 `true`. 결정당 정확히 1개 |
| `tags` | `'mistake'`(함정) / `'historical'` / `'expert'` / `'illegal'` / `'irreversible'`. 함정 옵션은 왜 매력적으로 보이는지와 왜 틀렸는지를 `rationale`에 설명 |
| `consequencesNarrative` | 선택 후 플레이어가 읽는 결과 서사. 사후정보 금지 적용 |
| `when?` | 선행 결정 의존(`{chose:{decision, option}}`)·상태 조건. 조건부 옵션은 `feasibility-present` 통과를 위해 해금 조건을 문장으로도 기재 |
| `scoreAdjust?` | 예외적 가감점만; 기본은 rating과 지표 곡선으로 채점 |
| `remediationConcept?` | 함정 선택 시 연결할 지식카드 id |

추가 규칙:
- 결정당 옵션 3~5개, 서로 배타적인 옵션은 `select.max`와 배타 조건(`when: {notFlag}`)으로 표현한다.
- 옵션 효과 크기는 반드시 체크리스트 5항(역사적 유사사례 / 문서화된 규칙 / [CAL] 노트+앵커) 중 하나로 정당화한다.
- 조건부 결과(예: 증자 성공/실패)는 확률이 아니라 상태 임계값(`CI`, `backstop` 비율)으로 분기한다.
- 불건전 행위 옵션(인출 지연·허위 공표)은 `tags: ['illegal', 'mistake']`와 감독당국 반응 R4를 명시한다.

## 9. 디브리핑·퀴즈 작성 규칙

**디브리핑 구성 순서**(UI 고정): 결과 요약(생존/폐쇄, 최종 KPI, 힌트 사용) → 7차원 점수 레이더(각 차원 = 50% 저작된 옵션 품질 + 50% 결과 지표) → 경로 비교 차트(플레이어 실선 / 역사 점선 / 전문가 점선, 결정 지점 마커) → 실수 Top3 → what-if → 교훈 → 퀴즈 → 출처.

**저자가 작성하는 것**
1. **역사 결과**: 실제 선택 시퀀스와 체크포인트(일별 유출·폐쇄 시점·손실). 게임의 역사 경로가 이를 ±15%로 재현해야 한다.
2. **전문가 경로**: 사후평가 기준 최선의 시퀀스와 그 결과. 생존 불확실성은 솔직히 명시한다("생존해도 징벌적 가격의 신자본 필요" 같은 캐비앳).
3. **교훈**: 3~5개, 각각 공식 사후평가·학술자료 인용(`sourceRefs` ≥1, 테스트로 강제). 학습목표(LO)와 1:1 이상 대응.
4. **단순화 노트**: `STYLIZED` 항목, 해소된 `VERIFY` 항목, 합성 기관과 실제의 차이(예: 은행 단독 vs 연결), 양식화한 일중 분포.
5. **실패 분기 반성 프롬프트**: 게임오버 시 표시할 질문(예: "생존 가능성이 사라진 시점은?")과 규칙 설명(어떤 임계값을 넘었는지).
6. **분기 설명**: `{fn, label}` 조건의 `label`은 필수이며 디브리핑에서 "왜 이 분기가 발생했는지"를 설명하는 데 쓰인다.
7. **what-if 포인트**: T+N 재시작이 의미 있는 결정 지점을 지정한다(전문가 경로와 갈라진 첫 결정 등).

**퀴즈 규칙**
- 5문항. 유형은 single / multi / numeric(허용오차) / true_false. 로컬 채점, progress 저장.
- 각 문항은 학습목표(LO) 하나에 매핑되고, 해설에 `sourceRefs` ≥1.
- 플레이 중 경험한 결정에서 답을 도출할 수 있어야 한다(사전/사후 ≥+2/5 게이트).
- numeric 문항은 허용오차를 명시한다(예: 유출 규모 ±10%).
- 함정 옵션의 왜곡된 매력을 묻는 문항을 1개 이상 포함한다.

## 11. 틱·인터럽트 저작 (L2)

턴을 서브턴 **틱**으로 쪼개면 한 턴 안에서 시계가 흐르고, 전화가 끼어들고, 결정에 마감 시각이 생긴다. 모든 필드는 선택적이다 — `ticks`를 쓰지 않은 턴은 종전과 완전히 동일하게 동작한다(틱 0이 곧 첫 틱이자 마지막 틱). 워크드 예제는 `tests/fixtures/miniTicks.ts`, 실제 적용 사례는 `src/scenarios/svb-2023`의 T3·T4·T5와 그 `calibration.md` §7이다.

### 11.1 틱 파이프라인 (저작 시 반드시 외울 순서)

```
지연효과(due) → eachTick → tickEffects(atTick) → 예정 이벤트(atTick) → 티커 → 인터럽트 개시
              → 지표 스냅샷 → 게임오버 → 마감 스윕(기한 지난 결정·인터럽트를 defaultOptionId로 확정)
```

이 순서가 곧 보정이다. 예: 같은 틱에서 `eachTick`의 유출이 `tickEffects`의 ΔCI보다 **먼저** 계산되므로, 마지막 틱에 ΔCI를 걸어도 그날의 유출률은 바뀌지 않는다. 반대로 **직전 틱에** 확정된 결정의 ΔCI는 다음 틱의 유출률을 바꾼다(런 상태 경계를 넘으면 크게).

틱 0은 `startTurn`이 `entryEffects` **뒤에** 실행한다. 따라서 턴 진입 효과 → 틱 0 파이프라인 → 틱 1… 이다.

### 11.2 필드 요약

| 필드 | 용도 | 린트 |
|---|---|---|
| `Turn.ticks` | 서브턴 틱 수 | 1 이상의 정수 |
| `Turn.tickLabels` | 틱별 시계 라벨(`['07:00', …]`) | 길이 = `ticks` |
| `Turn.eachTick` | 매 틱 적용(유출 슬라이스 자리) | `ConditionalEffects` |
| `Turn.tickEffects` | 특정 틱 적용(`atTick` 필수) | `atTick ∈ 0..ticks−1` |
| `Turn.ticker` | 일중 시계열 | `values` 길이 = `ticks`, `confidence` 경로 금지 |
| `GameEvent.atTick` / `jitter` | 이벤트 발화 틱 | `atTick ∈ 0..ticks−1` |
| `Decision.availableFrom` / `deadlineTick` | 결정 창 | 범위 검사 + `availableFrom ≤ deadlineTick` + 마감 있으면 `defaultOptionId` 필수 |
| `Decision.scoreWeight` | 점수 가중(인터럽트는 0.5) | ≥ 0 |
| `Turn.interrupts` | 중간 도착 결정 | 2~4 옵션, `lines` ≥ 1, `defaultOptionId` 필수, `timeoutSec > 0` |
| `DelayedEffectSpec.afterTicks` | 지연효과의 틱 정밀도 | 대상 턴이 틱 턴이어야 함 |

### 11.3 유출을 틱으로 나누기

틱 턴에서 `bankFx.runoffStep`은 **`entryEffects`가 아니라 `eachTick`** 에 둔다(엔트리에 두면 한 슬라이스만 실행되고 린트가 경고한다).

```ts
eachTick: [
  {
    id: 't3-runoff-tick',
    effects: [bankFx.runoffStep({ windowFraction: 0.55, profile: [0.35, 0.25, 0.2, 0.12, 0.08] })],
  },
]
```

- `profile` 길이 = `ticks`이고 **합이 1**이어야 한다(린트는 길이만 검사한다 — 합은 저자 책임).
- 각 슬라이스는 **턴 시작 잔액(`windowBase`)** 에 몫을 곱한다. 줄어드는 잔액이 아니다. 그래서 variance 0에서 슬라이스 합계가 종전 단일 호출과 **정확히** 일치한다 → 기존 체크포인트가 그대로 산다.
- 반면 **비율 입력(CI·증폭·완화)은 매 틱 실시간으로** 읽고, 증폭기는 **마지막 틱에서만** 리셋된다. 틱 중간에 걸린 증폭기는 남은 슬라이스에만 적용된다.
- 프로필 모양은 서사가 아니라 **근거**로 정한다: 전방 집중(개장 대기열), 중반 가속(소식 확산), 후방 감쇠(컷오프). 근거가 없으면 `[STYLIZED]`로 선언한다.

### 11.4 티커

```ts
ticker: {
  series: [
    { path: 'market.ownStock', mode: 'relative', values: [100, 97, 95, 93, 92] },
    { path: 'market.govt2yBp', mode: 'absolute', values: [507, 504, 501, 498, 495] },
  ],
}
```

- `values[0]`은 **틱 0 앵커**다. 틱 0에서는 아무것도 움직이지 않는다.
- `relative`는 `values[k]/values[k−1]` 비율을, `absolute`는 차분을 **현재 경로 값**에 적용한다. 즉 시리즈는 "수준"이 아니라 "궤적"이다 — 경로의 실제 시작값이 앵커와 다르면 궤적만 따라간다. 실제 수준을 맞추려면 `entryEffects`에서 `op(path, 'set', anchor)`로 먼저 앵커를 세운다.
- **티커는 `confidence`를 움직이지 않는다**(린트 오류). 가격 반응의 신뢰 효과는 ΔCI 이벤트가 이미 가격에 반영하고 있다.
- 이산 충격(개장 갭, 마감 급락)과 연속 궤적을 섞을 때는 **곱이 보존되도록** 재배분하고 보정 노트에 표로 남긴다. 기존 보정을 깨지 않는 유일한 방법이다.
- 장 마감 이후의 틱에서는 시리즈를 보합으로 둔다(같은 값 반복). 없는 시세를 만들지 않는다.

### 11.5 인터럽트

```ts
const call: Interrupt<BankState> = {
  id: 't3-i1-founders',
  interrupt: true,
  atTick: 1,
  jitter: 1,
  timeoutSec: 30,
  defaultOptionId: 't3-i1-defer',
  scoreWeight: 0.5,
  required: false,
  title: '…', prompt: '…',
  source: { kind: 'call', caller: 'Founders Fund 파트너', tone: 'urgent' },
  lines: [{ speaker: 'Founders Fund 파트너', text: '…' }],
  options: [ /* 2~4개 */ ],
}
```

- `Interrupt extends Decision`이므로 검증·효과·지연효과·점수·경로 비교가 **전부 재사용**된다. 점수 과대 반영을 막기 위해 `scoreWeight: 0.5`로 저작한다.
- `defaultOptionId`는 **필수**다. 무응답(마감 스윕·UI 타임아웃) 시 적용되므로 **역사 경로가 실제로 한 선택**을 기본값으로 둔다. 자동플레이의 `historical` 정책도 `historical: true` 옵션(또는 `paths.historical`)을 따라가므로 둘을 일치시킨다.
- `deadlineTick`은 **생략을 권장**한다. 생략하면 마감이 "실제로 열린 틱"(지터 반영)이 되어 어떤 variance에서도 정확히 한 틱의 응답 시간이 보장된다. 고정 값을 쓰면 지터가 마감보다 늦게 열리는 경우가 생긴다.
- `when`으로 조건부 인터럽트를 만들 수 있다(예: 사전 접촉이 없으면 감독관 전화가 오지 않는다). 조건이 거짓이면 아예 열리지 않는다.
- 옵션은 2~4개, 라벨은 한 줄에 읽히는 길이로. 한 옵션 안에서 상태에 따라 결과가 갈려야 한다면 **옵션을 둘로 나누지 말고** `fnEffect` 안에서 분기한다(플레이어가 아직 모르는 사실로 선택지를 늘리지 않는다).

### 11.6 결정 창(`availableFrom` / `deadlineTick`)

- **라이브 시계는 마감 틱에서만 멈춘다**(그 밖에는 인터럽트 도착·릴 재생·도움 시트·탭 비활성·턴 마지막 틱). 즉 `deadlineTick`이 없는 결정은 틱 턴에서 시간 압박을 전혀 만들지 않고, 하루가 마지막 틱까지 흐른 뒤 거기서 기다린다. **틱 턴의 모든 결정에 창을 명시하라.**
- `availableFrom`은 **보정 장치이기도 하다.** 결정의 효과가 같은 턴의 유출률에 영향을 준다면, 그 결정이 열리는 틱이 곧 "그날의 결과"를 바꾼다. 역사 경로가 재현해야 할 값이 있다면 **역사적 시각 순서**를 그대로 옮겨라(예: 오후 유출이 끝난 뒤에 있었던 콜은 마지막 틱에 연다).
- 마감 스윕은 **마감 다음 틱**에 돈다. 따라서 마지막 틱에 건 `deadlineTick`은 자동 확정을 일으키지 않는다(린트 경고 `deadline-last-tick`). 그 경우 무응답 처리는 UI 타이머(`timeLimitSec` + `defaultOptionId`)가 담당한다.
- `advanceTurn`은 남은 틱을 모두 소화한 뒤 **미확정 필수 결정이 있으면 예외**를 던진다. 필수 결정에는 반드시 `defaultOptionId`를 준다.

### 11.7 변동성(`scenario.noise`)

```ts
noise: { runoffSigma: 0.15, runoffCap: 0.3, tickerSigma: 0.01, tickerSigmaBp: 2, eventJitter: 1 }
```

크기(magnitude) 노이즈와 틱 지터만 있고 **분기는 만들지 않는다**. `variance: 0`에서는 엔진이 RNG를 아예 당기지 않으므로 기존 난수 스트림과 체크포인트가 불변이다. 테스트·체크포인트는 항상 variance 0(정본)으로 돌린다.

### 11.8 틱 전환 체크리스트

1. 전환 **전** 체크포인트 값을 소수점 셋째 자리까지 기록한다.
2. `runoffStep`을 `entryEffects` → `eachTick(profile)`로 옮긴다. 프로필 합 = 1, 길이 = `ticks`.
3. 이벤트·ΔCI·주가 충격에 `atTick`을 배분한다. 유출률에 영향을 주는 ΔCI는 파이프라인 순서를 따져 배치한다.
4. 티커 앵커를 `facts.ts`에 출처와 함께 넣는다. 미확인이면 `[VERIFY]`, 일중 분포는 `[STYLIZED]`.
5. 인터럽트의 `defaultOptionId` = 역사 선택. `scoreWeight: 0.5`.
6. 결정에 `availableFrom` / `deadlineTick`을 준다 — **보정을 먼저, UX는 그 다음**.
7. 전환 **후** 체크포인트를 다시 측정한다. 값이 움직였다면 `tolerance`를 넓히기 전에 **틱 배치를 먼저 고친다**. 그래도 안 되면 `absTolerance`(0 근처 목표값에만)를 쓰고 보정 노트에 이유를 남긴다.
8. `calibration.md`에 프로필·앵커·계수·체크포인트 재검증 표를 남긴다.

## 12. 대화·협상 저작 (D3)

결정 하나를 **여러 단계로 주고받는 대화**로 저작할 수 있다. 감독관에게 무엇을 얼마나 공개할지, 인수후보에게 할인율을 어디까지 약속할지를 한 번의 클릭이 아니라 대화로 고르게 하는 장치다. 모든 필드는 선택적이다 — `steps`가 없는 결정은 종전과 **완전히 동일하게** 동작한다. 워크드 예제는 `tests/fixtures/miniDialogue.ts`다.

### 12.1 핵심 계약: 대화는 언제나 기존 옵션으로 귀결한다

```
steps[0] ──reply.next──▶ steps[k] ──reply.next──▶ … ──reply.resolvesTo──▶ decision.options[i]
```

응답(`DialogueReply`)은 **`next`(다음 단계) 또는 `resolvesTo`(귀결 옵션) 중 정확히 하나**를 가진다. 대화가 무엇을 하든 마지막에는 그 결정이 원래 가지고 있던 옵션 하나를 고른다.

이것이 전부의 열쇠다. 로그에 남는 것은 여전히 `{ decisionId, optionIds }`이고, **응답 경로가 `DecisionRecord.path`로 나란히 기록될 뿐**이다. 그래서 검증·효과·지연효과·점수·경로 비교·디브리핑·결과 릴이 하나도 바뀌지 않는다. 리플레이는 경로를 **다시 걸어서 검증**한다 — 시나리오가 더 이상 허용하지 않는 경로는 조용히 통과하지 않고 `DecisionError('invalid-path')`를 던진다.

### 12.2 필드 요약

| 필드 | 용도 | 린트 |
|---|---|---|
| `Decision.steps` | 대화 단계 배열. `steps[0]`이 진입점 | `select`는 1~1이어야 함 |
| `DialogueStep.lines` | 상대 대사(`{ speaker, text }`) | ≥ 1 |
| `DialogueStep.replies` | 응답 2~4개 | 2~4개, id 중복 금지 |
| `DialogueStep.note` | 응답 위에 뜨는 안내(예: '약속한 ETA는 이후 이행 여부로 평가됩니다') | — |
| `DialogueReply.next` / `resolvesTo` | 다음 단계 / 귀결 옵션 | **정확히 하나**, 대상 존재 필수 |
| `DialogueReply.when` | 응답 노출 조건 | 조건 경로 검사 |
| `DialogueReply.effects` / `setFlags` | 응답 즉시 효과(보통 카운터·플래그) | op 경로 검사 |
| `DialogueReply.expert` | `{ rating, rationale }` — 자동플레이 walker가 읽는다 | — |
| `DialogueReply.trap` / `trapExplanation` | 함정 응답 | 함정에는 설명 필수 |
| `DecisionRecord.path` | 걸어간 응답 id 배열 | 0에서 생략(기존 로그 형태 보존) |

### 12.3 숫자 약속은 이산 선택지 + 카운터

자유 입력도 슬라이더도 없다. **재현 가능한 것만 기록한다.** 숫자 약속은 `commitReplies`로 이산 응답을 만들고, 이행 여부는 **나중에** 지연효과의 `when: { counter }`가 판정한다.

```ts
import { commitReplies } from '@/engine'

const haircutStep: DialogueStep<BankState> = {
  id: 'sale-haircut',
  lines: [{ speaker: '인수후보 CFO', text: '장부가 대비 할인율은 어디까지 받아들일 수 있습니까?' }],
  note: '여기서 약속한 할인율은 주말 실사에서 그대로 검증됩니다.',
  replies: commitReplies<BankState>('saleHaircutPct', [10, 25, 40], {
    unit: '%',
    next: (v) => (v >= 25 ? 'sale-regulator' : 'sale-walkaway'),
    expert: (v) => ({ rating: v >= 25 ? 75 : 30, rationale: '…' }),
  }),
}
```

- 생성되는 응답 id는 `saleHaircutPct-10` 같은 형태이고, 효과는 카운터를 **`set`** 한다(누적이 아니다 — 같은 대화를 다시 걸어도 두 배가 되지 않는다).
- 판정은 옵션의 `delayedEffects`에서 한다:

```ts
delayedEffects: [
  {
    afterTurns: 1,
    when: { counter: 'saleHaircutPct', lt: 25 },
    description: '약속한 할인율이 인수자 최소선에 못 미쳐 실사가 중단됨',
    effects: [confidence(-10, '매각 협상 결렬')],
  },
]
```

### 12.4 반드시 지킬 규칙 다섯

1. **`when`은 "이 결정을 요청받은 시점의 상태"를 본다.** `Option.when`과 같은 맥락이다. 따라서 **같은 대화 안에서 앞선 응답이 만든 카운터·플래그로 뒤 응답을 분기할 수 없다.** 대화 내부 분기는 `when`이 아니라 **`next`로** 한다(위 예시처럼 값에 따라 다음 단계를 바꾼다). `when`은 대화 이전부터 참인 사실(사전 접촉 플래그, 지표 수준)에만 쓴다. 이 규칙 덕분에 패널이 보여주는 응답과 엔진이 받아들이는 응답이 절대 어긋나지 않는다.
2. **응답 효과는 작게.** 카운터와 플래그 정도로 둔다. 상태를 실제로 움직이는 것은 귀결 옵션의 `effects`다. 응답 효과는 옵션 효과보다 **먼저**, 경로 순서대로 적용된다.
3. **응답 효과로 귀결 옵션의 `requires`를 만족시키려 하지 말 것.** 옵션 가용성은 대화 시작 시점 상태로 검증된다.
4. **모든 옵션이 어떤 경로로든 도달 가능해야 한다**(도달 불가는 경고). `when` 뒤에만 열리는 옵션이라면 경고를 감수하고 보정 노트에 적는다.
5. **`defaultOptionId`를 둔다.** 마감 스윕·UI 타임아웃은 대화를 건너뛰고 기본 옵션을 바로 확정한다(경로 없이). 인터럽트 대화라면 필수다.

### 12.5 무결성 린트 (`dialogue-*`)

| 규칙 | 수준 | 내용 |
|---|---|---|
| `dialogue-reply-target` | 오류 | `next`·`resolvesTo`가 둘 다 없거나 둘 다 있음 |
| `dialogue-next` | 오류 | `next`가 가리키는 단계 없음 |
| `dialogue-resolves-to` | 오류 | `resolvesTo`가 이 결정의 옵션이 아님 |
| `dialogue-unreachable-step` | 오류 | `steps[0]`에서 도달할 수 없는 단계 |
| `dialogue-cycle` | 오류 | `resolvesTo`에 닿지 못하고 영원히 순환할 수 있는 단계 |
| `dialogue-reply-count` | 오류 | 한 단계의 응답이 2개 미만 또는 4개 초과 |
| `dialogue-lines` | 오류 | 상대 대사 없음 |
| `dialogue-select` | 오류 | 대화 결정의 `select`가 1~1이 아님 |
| `dialogue-unique-ids` | 오류 | 단계 id 또는 한 단계 안의 응답 id 중복 |
| `dialogue-trap-explanation` | 오류 | 함정 응답에 `trapExplanation` 없음 |
| `dialogue-option-unreachable` | 경고 | 어떤 대화 경로로도 닿지 않는 옵션 |

### 12.6 자동플레이가 대화를 걷는 규칙

- `historical` / `expert`: 정책이 이미 고른 **목표 옵션**을 향해, `resolvesTo`가 (간접적으로라도) 그 옵션에 닿는 응답만 후보로 두고 그중 `expert.rating`이 **가장 높은** 것을 고른다.
- `worst`: 목표 없이 자유롭게 걷되 **`trap` 응답을 먼저**, 없으면 `expert.rating`이 가장 낮은 것을 고른다.
- `random`: 시드 RNG로 뽑는다.
- 어느 정책이든 **확정 가능한 옵션에 닿지 못하는 응답은 고르지 않는다.** 걸어간 경로는 `DecisionRecord.path`에 기록되므로 자동플레이 로그도 그대로 리플레이된다.
- `expert.rating`이 없는 응답은 50으로 취급한다. 역사·전문가 경로를 의도대로 걷게 하려면 **모든 응답에 rating을 붙여라.**

### 12.7 저작 체크리스트

1. 결정의 옵션을 **먼저** 확정한다. 대화는 그 옵션들로 가는 길일 뿐이다.
2. 단계는 3개 안팎, 단계당 응답 2~4개. 5단계를 넘으면 결정을 둘로 나누는 편이 낫다.
3. 각 단계의 `lines`는 **상대가 실제로 물어봤을 법한 한두 문장**으로. 배경 설명은 `Decision.context`에 남긴다.
4. 숫자 약속은 `commitReplies` + 지연효과 판정. `note`에 "이후 이행 여부로 평가됩니다"를 명시한다.
5. `pnpm test`로 `dialogue-*` 린트 0건을 확인하고, `autoplay`의 `historical`/`expert` 경로가 의도한 옵션에 도달하는지 확인한다.
6. `calibration.md`에 경로별 카운터 값과 그것을 판정하는 지연효과를 표로 남긴다.
