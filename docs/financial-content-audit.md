# 금융 내용 정확성 검토

검토일: 2026-09-14. 대상: 은행·증권·운용·정책 실무자의 개인 훈련. 프로젝트의 설명과 계산·장부·사건 시점을 직접 대조하고, 확인 가능한 감독당국·중앙은행 원문으로 검증했다.

**내용 오류가 있었다.** 특히 정책 발표를 현금 수령으로 처리하거나, 회계상 반영된 손실을 다시 빼도록 설명하는 부분은 훈련자의 판단을 바꿀 수 있어 코드와 설명을 함께 수정했다. 아래의 ‘수정’은 이번 작업에서 반영했다는 뜻이며, 전체 역사 자료를 독립적으로 전수 검증했다는 뜻은 아니다.

## 검토 범위와 방식

- 플레이 가능한 13개 시나리오의 구성·초기 상태·사실 원장·타임라인·디브리핑을 대상으로 교차 검색하고 주요 수치와 사건 순서를 대조했다. 모든 턴의 역사적 UTC 오프셋은 시간대 데이터베이스로 자동 점검했다.
- 공통 지식카드 20개, 프레임워크 10개, 용어집·규제 요약·KPI 설명에서 중복된 정의와 산식을 검색했다. LCR·자본·예금 유출·증권사 유동성·LDI·프라임브로커 지표는 실제 계산 함수를 기준으로 설명을 대조했다.
- 실제 규정, 역사적 관측값, 합성 기관의 가정, 시나리오 채점·종료 조건을 구분했다. 실제 참가자 평가나 외부 실무자 검증을 전제로 하지 않았다.

태영 모형의 금융기관 약정 0.4조에 적용하면 해당 항목의 총유출은 종전 0.12조에서 0.4조로 증가한다. 이는 합성 기관의 LCR 입력 변경이며, 실제 태영이나 주채권은행의 규제 LCR을 새로 추정한 것이 아니다.

브라우저 점검에서 ELS의 CP 만기를 PF 자체매입처럼 부르는 공통 화면 문구도 발견했다. 이를 차환 부족분으로 바꾸고, 대차대조표 미니뷰의 ‘30일’ 표기를 실제 미처리 구간 합계로 고쳤다. 정책자금의 미입금·실행 잔액과 후속 처리 건수를 표시하고, 증권금융·거래은행 대출을 조달 잔액에서 확인할 수 있게 했다.

## 검증 결과

- 전체 테스트: **90개 파일, 1,365개 통과, 기존 건너뛰기 8개**. 기존 역사 경로·전문가 경로·무결성·사실 원장·재생 검사를 포함한다.
- 신규 회귀 검사 21개: 금융 산식·지표 설명 6개, 13개 시나리오의 UTC 오프셋, ELS 정책대출·담보 장부 및 약정/결제/중복 입금/재생 검사 2개.
- 최종 화면 문구·후속 처리 표시 수정 후 관련 엔진 검사 24개·화면 검사 6개 통과.
- TypeScript, ESLint, 프로덕션 빌드 통과. 기존 500kB 초과 번들 경고는 남아 있다.
- 최종 버전 변경 후 무결성·ELS·태영·저장 재생 재검증: 12개 파일, 166개 통과·2개 건너뛰기.
- ELS T7을 실제 Chromium의 1440px·390px 화면에서 확인했다. 약정 단계에서는 외화가 늘지 않고 결제 후 3,000억원 증가했으며, 페이지 오류와 가로 넘침은 없었다.

테스트 통과는 현재 코드와 명시한 기대값의 일치 여부를 확인한다. 모든 사실 원장의 외부 원문이나 금융 모델의 실증 타당성을 보증하지 않는다.

| 은행 FI 약정 상대방 | 기존 상태에 은행/비은행 구분이 없다. 100% 매핑은 보수적 가정이며, 실제 상대방별 데이터가 생기면 분리 입력해야 한다. |
| 국내 역사 자료 및 최신 제도·소송 | 일부 저축은행·새마을금고·PF 자료의 미확인 원문, ELS 세부 규정, CS AT1 후속 소송 결과 등은 기존 사실 원장·서지의 확인 과제가 남아 있다. 이번에 확인하지 않은 항목의 검증 표시는 올리지 않았다. |
| 채점과 임계값 | 전문가 점수·신뢰지수·실행률·폐쇄 조건은 교육 모형이다. 특정 조직의 실제 역량이나 법정 감독 판단으로 일반화하지 않는다. |

## 저장된 진행 상황에 미치는 영향

실제 장부 처리와 선택 조건이 달라진 `els-margin-2020`, LCR 입력이 달라진 `taeyoung-pf-2024`는 시나리오와 목록 버전을 **2**로 올렸다. 기존 버전 1의 선택 기록을 새 규칙으로 조용히 다시 계산하지 않도록 기존 저장 버전 검사를 사용한다. 완료 기록을 삭제하지 않으며, 두 시나리오의 이전 진행 중 세션은 새 버전으로 다시 시작해야 한다.
