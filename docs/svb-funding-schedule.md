# SVB 결제·자금 일정표

## 적용 범위

은행 자금 실무자가 현재 현금, 남은 구간의 지급 추정, 미인출 한도, 담보 이전분의 반영 시점을 함께 확인하는 화면이다. 상황실의 `자금·마감 확인 → 결제·자금 일정 자세히`에서 열고, 모바일 결정 탭에서도 같은 표를 열 수 있다.

SVB의 3월 9일 오전(T3)·오후(T4)에 시간별 지급 추정을 제공한다. 다른 구간에서는 현재 잔고·한도와 이미 공개된 마감 점검을 표시한다. 시간별 지급 데이터가 없는 구간은 **미산정**으로 표시하며 0원 지급으로 간주하지 않는다.

## 사실과 가정

- 현재 현금과 미인출 한도는 플레이 상태에 이미 반영된 훈련 수치다. 실제 SVB의 개별 지급 원장을 재현한 값이 아니다.
- [Fed의 SVB 사후평가](https://www.federalreserve.gov/publications/files/svb-review-20230428.pdf)의 인쇄면 4쪽과 59–60쪽은 급격한 예금 유출과 비상 조달·담보 이전의 준비 부족을 뒷받침한다. 시간별 송금 금액이나 훈련의 처리 시각을 입증하는 출처로 사용하지 않는다. 2026-09-13 확인.
- [BIS 일중 유동성 모니터링 문서](https://www.bis.org/publications/201304-standards-monitoring-tools-intraday-liquidity-management)는 일중 유동성 관리의 배경 자료다. 화면의 추정치를 규제 보고 수치나 실제 결제 의무로 표시하지 않는다.
- 오전 55%·오후 45%와 각 구간 내 시간별 배분은 기존 시나리오의 훈련 가정이다. 새 숫자를 별도 저술하지 않고 실제 `runoffStep`의 비율과 배분을 읽는다.
- 목요일 17:00은 훈련의 마감 잔고 점검 시각이다. 개별 송금·cash letter의 정확한 지급액과 실제 결제 마감을 추가했다고 주장하지 않는다.
- 담보 이전 잔액은 실제 `t6-settle`이 실행되는 금요일 05:00에 **한도**로 반영된다. 야간 지원이나 이관 지연에 따라 처리 금액·시점이 달라질 수 있다. 현금에 쓰려면 인출 결정이 필요하다.

## 계산과 표시

현재 시점의 처리는 이미 끝난 상태에서 화면을 그린다. 따라서 현재 시점 이후의 배분만 추정한다.

1. 구간 시작 예금 잔액(`windowBase`), 현재 신뢰·인출 성향, 기존 시간 배분을 `projectRunoff`에 전달한다.
2. 현재 현금에서 남은 시점별 지급 추정을 차례로 차감한다.
3. 잔고가 처음 음수가 되는 시점과 구간 종료 부족액을 표시한다. 현금이 이미 음수라면 **현재 현금 부족**으로 따로 표현한다.
4. 미인출 한도·담보 이전분·미실행 증자·향후 선택의 현금 효과는 더하지 않는다.
5. 이후 사건·결정·변동성은 예측 실행하지 않는다. 그 변화가 실제로 발생하면 갱신된 상태에서 다시 추정한다. 표를 열어도 난수·결정 로그·점수는 변하지 않는다.

시간별 표는 같은 통화 단위와 소수 자릿수를 사용한다. 추정 부족은 경고 색상과 ‘부족’ 문구로 표시한다. 현재 현금 부족은 현재 위험 색상을 쓴다. 1일 예상 유출이나 LCR을 지급 마감 부족액 대신 사용하지 않는다.

마감 점검은 T3에 공개하고 T5 도달 뒤 T4 마지막 기록의 잔고를 보여 준다. 이미 반영된 유출을 다시 차감하지 않으며, T5의 야간 조달로 현재 잔고가 달라져도 마감 기록은 유지한다. 원본 시점 기록이 없으면 확인 불가로 표시한다.

전문가 모드에서도 현재 운영 상태에 기반한 추정은 제공한다. 사후 출처 링크는 감추며, 필요한 지표가 지연 보고되도록 저술된 경우에는 현재 시점 추정을 보류한다.

## 구조와 호환성

- `ScenarioDefinition.fundingPlan`: 시간별 유출 효과 참조, 한도 반영 시점·조건, 공개 시점이 있는 잔고 점검을 저술한다.
- `src/scenarios/svb-2023/funding.ts`: SVB 전용 메타데이터. 금액과 시간 배분의 중복 정의를 피한다.
- `src/lib/fundingSchedule.ts`: 읽기 전용 계산. 미래 이벤트를 실행하거나 저장 상태를 변경하지 않는다.
- `validateFundingPlan`: 존재하는 구간·틱, 실제 유출/한도 반영 효과, 시간 배분, 공개 순서, 출처를 검증한다.
- 기존 결정·저장·점수·시나리오 수치 보정은 유지한다. 재생된 상태에서 다시 계산하므로 별도 저장 마이그레이션은 필요 없다.
- 공통 `facilityPending` 표기에서 보장되지 않는 ‘다음 구간’을 제거하고 ‘반영 대기’로 통일했다. SVB의 정확한 반영 시점은 일정표가 담당한다.

## 검증

- 계산 회귀: T3/T4의 조건을 고정하면 엔진의 실제 시간별 현금 차감과 소수점 10자리까지 일치한다.
- 현금과 한도: 차입 한도 100·이전 중 60이 있어도 현금 −1은 부족 상태다. 실제 인출 10 실행 후에만 현금과 예상 잔고가 10 증가한다.
- 순수성·복원: 미래 사건 변경에 추정이 영향받지 않고, 난수 상태를 변경하지 않으며, 변동성 1의 JSON 결정 로그 재생 후 같은 결과를 만든다.
- 마감: 야간 조달 후 현재 잔고가 달라져도 마감 기록은 유지된다. 미산정·누락 기록·미공개 점검의 경계를 검증한다.
- 화면: 모바일에서 표를 펼쳐도 결정을 확정하지 않는다. 전문가 출처 제한과 기존 후속 처리 표시를 유지한다.
- 전체 회귀 1,302개 통과, 기존 건너뛰기 8개. TypeScript 포함 빌드와 ESLint 통과. 기존 500kB 초과 번들 경고는 남아 있다.
- Chromium 1440×1000, 390×844에서 가로 넘침과 외부 빈 세로 스크롤 없음. 모바일 표 전체가 컨테이너 안에 들어온다. 변동성 1에서 진행 상황을 저장하고 실제 새로고침 후 일정표 전체가 동일함을 확인했다. 브라우저 오류 없음.

## 남은 콘텐츠 작업

개별 지급의 금액·통화·확정 여부·법적/계약상 마감·담보권과 결제 선후관계가 검증된 원장은 아직 없다. 원문 자료로 저술하기 전에는 확정 지급 부족액을 계산하지 않는다. 이번 추정 표를 실무자에게 검토받아 용어와 의사결정 도움 여부를 확인한 후, 레고랜드·LDI의 서로 다른 차환·마진 결제 구조를 별도로 저술한다.
