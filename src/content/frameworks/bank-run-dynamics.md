## 개요

뱅크런(bank run)은 예금자가 은행의 지급능력·유동성을 의심해 동시에 인출하는 현상이다. 런은 선형으로 진행하지 않는다. 신뢰가 특정 문턱을 넘으면 유출률이 자릿수 단위로 뛰고, 하나의 사건(손실 공개, 피어 실패, 강등)이 상태를 바꾼다. 이 플랫폼은 그 비선형성을 [시장 신뢰지수](term:confidence-index)(Confidence Index, CI, 0~100)로 구동되는 4개 [런 상태](term:run-state)(S0~S3)로 모델링하며, 저작 가이드의 보정값은 2023년 이후 사후평가에서 관측된 런 속도에 앵커돼 있다. 계수는 경험 상수가 아니라 보정값이지만, 앵커는 실제다.

## 핵심 규칙과 수치

**런 상태**

| 상태 | 이름 | CI 범위 |
|---|---|---|
| S0 | 평온 | ≥ 70 |
| S1 | 우려 | 50~69 |
| S2 | 공개 런 | 30~49 |
| S3 | 붕괴 | < 30 |

CI_t = clamp(CI_{t−1} + ΣΔCI_events + 0.4 × 자사주가수익률%).

**ΔCI 이벤트표**

| 이벤트 | ΔCI | 앵커 |
|---|---|---|
| 손실 공개 + 미백스톱 증자 | −25 | SVB 3/8→9 |
| 완전 백스톱 증자 | −5 | CS 2022.10 |
| 1노치 강등 / 다노치·정크 강등 | −5 / −15 | |
| 증자 실패·철회 | −25 | |
| 가시적 유출 > 10%/일 | −15 | |
| 동종 피어 실패 | −5 | |
| 감독당국 확인 유동성 ≥ 무보험의 50% | +10 | FRC 3/12 |
| 컨소시엄 예금 | +10 | |
| 전면 보증 | +40 | |
| 지급 지연 가시화 | −20 | 시그니처 |
| 수치 없는 CEO "침착" 콜 | −3 | |

**세그먼트별 기본 일일 유출률(S0/S1/S2/S3)**: 무보험·동질·네트워크·디지털(VC 스타트업) 추세/3%/35%/95% · 무보험 대기업·펀드(운영성) 0/2%/20%/80% · 보험 소매·SME 0/0.2%/3%/10%(창구 상한 10%/일) · 무보험 고액자산가 0/1%/10%/50% · 도매 무담보는 만기 시 100% 미갱신. 일일 유출 = 잔액 × min(상한, 기본 유출률 × Π증폭 × Π완화).

**증폭 계수(×)**: 증자 실패·철회 2.0(S2→S3) · 48시간 내 동종 피어 실패 1.3 · 네트워크 조율 권고 1.5 · 다노치·정크 강등 1.3 · 지급 지연 가시화 1.5(→S3) · SNS 바이럴 1.2 · 정보 공백 1.2 · 거짓 백스톱 발표 후 모순 1.5.

**완화 계수(×)**: 세그먼트 커버 전면 보증 0.1(익일)/0.05 · 피어 암묵 보장 인식 0.5(무보험; FRC 제외) · 대형은행 컨소시엄 예금 0.6 · 검증 가능 유동성 공표(≥ 무보험 50%, 사실이어야 함) 0.7(모순 시 1.5) · 완전 백스톱 증자 종결 0.7 · 예금금리 인상 0.95(S1만) · 보험 스윕 프로그램(5일간 무보험 ≤ 20% → 보험 전환).

## 위기에서의 작동 방식

런은 정보의 문제이자 조율의 문제다. 예금자는 대차대조표를 볼 수 없으므로 신호로 판단하고, 확인 가능한 숫자가 없으면 최악을 가정한다. [무보험](term:uninsured-deposits)이면서 동질적이고(같은 산업), 네트워크로 연결되어 있으며(VC·단체 채팅), 디지털 채널로 즉시 송금할 수 있는 예금 기반은 조율 비용을 0에 가깝게 만든다. FSB는 2023년 3월의 런을 "fast-fail" 시나리오로 규정했다. 가장 빠른 3개 런은 일 20~30%, 중위 런도 7%/일로 과거(1%/일)의 7배였고, SVB는 실행분과 3/10 계획분을 합치면 80%를 넘었다. 과거 사례인 WaMu(16일 10.1%), 컨티넨탈 일리노이(10일 30%)와 비교하면 시간 축이 한 자릿수 일로 압축된 것이다 [출처: fsb-depositor-behaviour-2024]. Basel 30일 [유출률](term:run-off-rate)은 규제 하한이며, 2023년 런은 30일 허용치를 1~2일에 소진했다.

상태 전이는 되돌리기 어렵다. S2에서 증자가 실패하면 유출이 두 배가 되며 S3로 떨어지고, 지급 지연이 가시화되면 곧바로 S3다. 반대로 전면 보증(ΔCI +40, 완화 0.1)은 하루 만에 런을 끝내지만, 개별 기관이 계획에 넣을 수 있는 수단이 아니다. 증폭 계수는 곱으로 겹친다 — 피어 실패 × 네트워크 권고 × 침묵 ≈ ×2.3이 최악 조합이다.

## 실무 체크리스트

- 자기 기관의 CI에 해당하는 지표(주가, CDS, 예금 순유출, 언론·SNS 언급량)를 정해 런 상태를 매일 판정한다.
- 예금을 보험/무보험뿐 아니라 동질성·네트워크·채널(디지털 송금 가능 여부)로 세그먼트화한다.
- S1→S2 트리거(손실 공개, 강등, 피어 실패)가 임박하면 그 전에 백스톱·담보·커뮤니케이션을 갖춘다.
- 최악 세그먼트가 하루 25~35% 빠지는 시나리오로 생존 일수를 계산하고, 보험 소매의 창구 상한(10%/일)에 기대지 않는다 — 디지털 채널에는 상한이 없다.
- 완화 조치는 "사실이어야" 작동한다 — 검증 불가능한 안심 발언은 모순 시 ×1.5 증폭으로 되돌아온다.
- 소셜미디어·업계 네트워크 모니터링을 유동성 조기경보에 포함한다.

## 이 플랫폼에서

`runoff` 엔진이 위 세그먼트 유출률·증폭·완화 계수를 그대로 구현하며, `runState`·`confidence`(경고 60·위반 40)·`dailyOutflowPct`(경고 3%·위반 10%)·`cumulativeOutflowPct`(경고 10%·위반 25%)·`survivalDays`가 대시보드 지표다. 저작 린트 `runoff-in-range`는 시나리오의 유출률 오버라이드가 위 범위 안에 있는지 검사하고, `historical-path-reproduces`는 역사 경로가 일별 유출·폐쇄 시점을 ±15%로 재현하는지 확인한다. `svb-2023`이 S0→S3 전이를 시간 단위로 다루고, 계획 중인 `mg-run-2023`·`savings-bank-2011`·`credit-suisse-2023`·`lehman-2008`이 각각 완화, 조건부 발언 실패, 일별 유출, 도매 조달 런을 다룬다.
