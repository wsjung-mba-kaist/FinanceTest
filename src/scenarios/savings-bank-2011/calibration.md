## 1. 상태 매핑 — `CentralBankState` 위에 금융당국 올리기

`CentralBankState`는 외환당국용 타입이다. 공유 `central_bank` fx 모듈이 없으므로
`korea-imf-1997/fx.ts`·`credit-suisse-2023/fx.ts`와 같은 방식으로 시나리오 안에 `fx.ts`를 두고,
필드를 다음과 같이 재해석했다. 대시보드 라벨은 `kpis`에서 다시 붙인다.

| 엔진 필드 | 이 시나리오의 의미 | 지표 키 | KPI |
|---|---|---|---|
| `reserves.usable` | 예금보험기금 **저축은행계정** 가용재원(조원) | `usableReserves` | ✔ primary |
| `reserves.gross` | 예금보험기금 전 계정 합계 | — | |
| `reserves.forwardCommitments` | 확정된 지원 확약(삼화 정리) | — | |
| `external.shortTermDebt` | 향후 1년 예상 **정리소요액** | `guidottiRatio` = 가용/소요 | 임계값만 |
| `external.monthlyImports` | 월평균 예금대지급 소요 | `importCoverMonths` | |
| `bankingSystem.failedBanks` | 영업정지 누계 기관 수 | `failedBanks` | ✔ primary |
| `bankingSystem.distressedBanks` | 부실 징후 기관 수 | `distressedBanks` | |
| `bankingSystem.capitalShortfall` | 자본부족 추정 | `capitalShortfall`(custom 사본) | |
| `imf.stage` / `imf.committed` | 구조조정 **특별계정**의 입법 단계와 약정 재원 | `imfCommitted`, `specialAccountTn` | 체크포인트 |
| `sovereign.spreadBp` | 회사채 AA− 3년 − 국고채 3년(bp) | `sovereignSpreadBp` | **KPI 아님** |
| `fx.spot` | 원/달러 종가 | `fxSpot` | |

> **`sovereign.spreadBp` 재사용에 대하여.** `CentralBankState`에는 신용스프레드를 담을 칸이 없어
> 이 필드를 신용스프레드로 썼다. 엔진이 내보내는 행 라벨("국가 스프레드/CDS")은 맞지 않으므로
> **KPI로 노출하지 않는다.** `market.creditSpreadIgBp`와 항상 같은 값이며 `sync()`가 유지한다.

`bankingSystem.capitalShortfall`과 `external.shortTermDebt`는 엔진이 지표 행으로 내보내지 않으므로
`custom.capitalShortfall` · `custom.resolutionNeed` 사본을 두고 `sync()`가 갱신한다. 턴 텍스트의
`{{metric:...}}` 치환이 이 사본을 읽는다.

## 3. 전염 모형 (`fx.ts`의 심장)

### 3.1 산식

```
runState  = runStateFromCi(CI)                       S0 ≥70 · S1 50~69 · S2 30~49 · S3 <30
slice_g   = base_g × BASE_RATE[g][runState] × spill_g × dampener × days × profile[tick] × noise
```

`base_g`는 **턴 시작 잔액**(`counters.wb*`, 틱 0에 고정)이다. 줄어드는 잔액이 아니다 —
그래서 variance 0에서 슬라이스 합계가 틱 없는 단일 호출과 **정확히** 일치한다(§6.3에서 검증).
반면 `runState`·`spill`·`dampener`는 매 틱 실시간으로 읽는다.

### 3.2 무리별 · 런 상태별 일일 인출률 `BASE_RATE` [CAL]

| 무리 | S0 평온 | S1 우려 | S2 공개 런 | S3 붕괴 |
|---|---|---|---|---|
| `busan` | 0.20% | 0.70% | 2.00% | 5.00% |
| `peer` | 0.10% | 0.30% | 0.85% | 2.20% |
| `sound` | 0.02% | 0.06% | 0.16% | 0.45% |

**앵커**: 2011년 2월 업권 수신 △1.83조 가운데 대부분이 2/17~2/22에 몰렸다는 것(ECOS 월말 계열 +
2/19 보도자료의 "예금인출 사태가 계속"). S2에서 하루치 합계는
`6.5×2.0% + 11.2×0.85% + 55.85×0.16% ≈ 0.13 + 0.10 + 0.09 = 0.32조`이고, 전염 계수가 붙으면
2/18~2/21 창(2영업일)에서 0.4~0.5조가 된다. 2월 전체로는 1.2~1.5조 수준이며 나머지는 정지 기관의
예금이 얼어붙어 생기는 이탈로 본다.

`sound`의 S3 0.45%/일은 "건전 저축은행에서도 하루 0.25조가 빠진다"는 뜻이다. 이보다 높게 잡으면
(초기값 0.68%였다) 업권 전체가 한 턴 만에 붕괴하고 역사 경로가 재현되지 않는다 — 실제로 첫 조정에서
역사 경로가 T4에 `sector_run`으로 끝났고, 이 값을 낮춰 해결했다.

### 3.3 전염 계수 `spill`

```
계열(busan) 잔여 > 0   spill_busan ×= 1 + 1.6 × (정지된 계열 수신 / 정지 직전 계열 수신)
취약군(peer) 잔여 > 0  spill_peer  ×= 1 + 0.7 × (같은 비율)
다른 무리              spill      ×= 1 + 0.35 (peer) · 1 + 0.21 (sound)
상한 3.2 · 턴마다 1을 향해 −18% 감쇠(`decaySpill`)
```

- **계열 1.6 vs 취약군 0.7**: 계열은 자금·전산·평판을 공유하므로 "옆 창구"가 같은 기관으로 읽힌다.
  취약군은 같은 명단에 있을 뿐이다. 이 차이가 이 시나리오가 가르치려는 것 전부다.
- **역산**: 2/17에 계열 수신의 40%(2.6/6.5)를 정지 → `spill_busan = 1 + 1.6×0.4 = 1.64`,
  거기에 2/16 소문(×1.12)이 곱해져 2/17 종가 기준 1.81. 그 계수로 2/18~2/21 창에서 잔여 3.9조의
  일일 인출률이 2.0% → 3.6%로 올라 이틀 만에 지급 불능이 명백해진다 — 2/19 보도자료의 판단과 같다.
- **잔여가 0이면 항이 사라진다**(`affiliateSpill(share, 0) === 1`). 계열 일괄 정지의 유일한 이득이
  이것이고, 테스트가 직접 검증한다.
- `partialSuspensions` 카운터와 `partial_affiliate_suspension` 플래그는 **계열에만** 기록된다.
  취약군을 나눠 정지한 것은 전염을 만들지만 "계열을 쪼갰다"는 서술과는 다르기 때문이다.

### 3.4 유동성 백스톱

```
backstop(amount)  →  custom.backstopTotal += amount
                     counters.dampener ×= (1 − min(0.25, amount/24))
runoffStep        →  backstopRemaining −= 인출액 × 0.6   (60%를 백스톱이 결제한다)
소진 시            →  flag backstop_exhausted, ΔCI −5, 모든 무리 spill ×1.25
```

6조원 → 완화 ×0.75. 24조원을 분모로 둔 것은 "업권 수신의 3분의 1을 약정하면 인출률이 4분의 1로
줄어든다"는 상한을 주기 위한 보정이며, 6조가 실제 규모이므로 그 지점의 값(×0.75)만이 의미를 갖는다.

**T0.D2 옵션 a(3조)와 b(6조)의 차이**: a를 고르면 T2 진입 시 `backstop(1.5)`가 추가되어 총 4.5조에
그친다(당일에 모으면 다 모이지 않는다 [CAL]). b를 고르면 T0에 이미 6조이고 `backstop_ready` 플래그가
T0에 서므로 `timeliness`의 조기 확보 항목을 만족한다.

## 4. 예금보험기금 저축은행계정

### 4.1 초기값과 대지급 소요

`reserves.usable = 4.8조` [CAL]. 2010년말 저축은행계정이 이미 누적적자였다는 것이 전제이고
(그 규모 2조 8,282억원은 언론 2차 인용뿐 — §11), 4.8조는 "잔여 + 예보채 발행·계정 간 차입으로
즉시 동원 가능한 재원"이다.

| 사건 | 정지 기관 | 예금(조) | 초과예금(조) | 후순위채(조) | payout(조) |
|---|---|---|---|---|---|
| T2 `scope_partial` | 부산·대전 2 | 2.6 | 0.0980 | 0.0700 | 1.6 |
| T2 `scope_group` | 계열 5 | 6.5 | 0.1613 | 0.1132 | 2.6 |
| T3 계열 잔여 | 3 | 3.9 | 0.0633 | 0.0432 | 1.0 |
| T3 보해 | 1 | 0.55 | 0 | 0 | 0.35 |
| T4 도민(외생) | 1 | 0.35 | 0 | 0 | 0.25 |
| T6 경은(외생) | 1 | 0.20 | 0 | 0 | 0.20 |
| T6 7개사 | 7 | 3.2 | 0.1560 | 0.2232 | 4.2 |

초과예금·후순위채의 **합계가 공표치와 정확히 일치하도록** 분할했다:
부산 계열 0.0980 + 0.0633 = **0.1613**(1,613억), 0.0700 + 0.0432 = **0.1132**(1,132억).
`scope_group`을 고르면 T2에 한 번에 0.1613/0.1132가 들어가므로 **두 경로 모두 T3 체크포인트를
만족한다.** 보해·도민·경은에는 0을 넣었다 — 개별 공표치가 없기 때문이며 선언된 단순화다.

`payout`은 [CAL]이다. 역사 경로에서 저축은행계정이 T7까지 양수로 남고(4.8 → 1.86), 유예 가산(×1.30)과
특별계정 미설치가 겹치면 음수가 되도록 잡았다. §10의 `fund_exhausted` 도달 경로가 그것을 보인다.

### 4.2 구조조정 특별계정 (`imf` 필드)

| 단계 | 의미 | 트리거 |
|---|---|---|
| `requested` | 예금자보호법 개정 착수 | T1.D2-d, T3 인터럽트 a/d |
| `agreed` | 특별계정 설치 (`committed` 15조) | T5.D1-a/d |
| `disbursed` | 인출 | T7.D1-a |

`committed = 15`는 **설치 당시 소요 예상 15조원**(fsc-86263)이고 T5 체크포인트가 그 값을 검사한다.
실제 투입 27.2조원은 디브리핑 전용이다. 인출액은 T5에서 4.5조(a) / 5.0조(d), T7에서 2.0조로
[CAL]이며, 역사 경로가 T6의 4.4조 소요를 감당하고도 양수로 남도록 맞췄다.

## 5. 적기시정조치 유예 (`forbear`)

```
growth = months × lossGrowthPerMonth
capitalShortfall ×= (1 + growth)
external.shortTermDebt ×= (1 + growth)
counters.forbearanceCost += growth            ← 이후 모든 suspend의 payout이 ×(1 + forbearanceCost)
counters.dampener ×= 0.9                      ← 오늘의 인출은 실제로 줄어든다
ΔCI +3
```

**함정이 함정인 이유가 여기 있다.** 유예는 오늘의 지표를 실제로 좋게 만든다(완화 ×0.9, ΔCI +3).
비용은 `forbearanceCost`가 **정리하는 날의 대지급 소요를 부풀리는 방식**으로만 청구된다.

| 옵션 | 규모 | growth |
|---|---|---|
| T0.D1-c 계열 5개사 6개월 유예 | 5개사 × 6개월 × 5%/월 | **+0.30** |
| T6.D1-c 13개사 3개월 유예 | 13개사 × 3개월 × 6%/월 | **+0.18** |
| T3.D1-b 유동성 지원으로 버티기 | 지연효과 | +0.20 |
| T3.D1-c 보해 정지 유예 | 지연효과 | +0.08 |
| T4.D2-b 유예 해제 | | **−0.12** |
| T7.D2-b 유예 요건 법제화 | | **−0.10** |

월 5%는 "6개월 유예하면 자본부족액이 30% 자란다"는 뜻이다. 앵커는 간접적이다 — 특별계정의 실제 투입액
27.2조원이 설치 당시 예상 15조원의 1.81배였다는 사실(fsc-86263)과, 정리가 2015년까지 이어졌다는 사실.
이 시나리오는 그 초과의 **일부**만을 유예에 귀속시킨다.

검증: 같은 경로에서 T0.D1만 c(유예) vs a(정지)로 바꾸면 **T6의 기금 감소가 5.12조 vs 3.80조**다
(같은 7개사 정지인데 1.32조 더 든다). 테스트 `forbearance grows the eventual payout`이 이를 검사한다.

## 6. 서브턴 틱 (L2)

### 6.1 왜 이 세 턴인가

| 턴 | 날짜 | 틱 | 이유 |
|---|---|---|---|
| T2 | 2/17(목) | 5 | 의결 → 발표 → 창구 → 마감이 **하루 안에** 일어났다 |
| T3 | 2/18(금)~2/21(월) | 5 | 금요일 마감 → 토요일 의결 → 주말 → 월요일 개점 |
| T6 | 9/16(금)~9/19(월) | 5 | 9/18이 **일요일**이었다 — 같은 구조가 반복된다 |

### 6.3 슬라이스 합계 = 단일 호출 (variance 0)

## 7. 다단계 대화 (D3)

### 7.1 T2.D1 — 관계기관 합동 발표 문안

```
t2-d1-forum ─ forum-joint / forum-fsc-only ─▶ t2-d1-backstop
             └ forum-silent ────────────────▶ 옵션 c
t2-d1-backstop ─ commitReplies('pledgedBackstopTn', [3, 6, 12]) ─▶ t2-d1-promise
t2-d1-promise  ─ commitReplies('pledgedNoSuspensionDays', [0, 30, 120]) ─▶ 옵션 a / c / b
                 └ promise-full-protection ──────────────────────────▶ 옵션 d
```

| 카운터 | 값 | 귀결 옵션 | 지연 판정 |
|---|---|---|---|
| `pledgedBackstopTn` | 3 / **6** / 12 | — | `≥12`이면 T3 진입 시 ΔCI −6, 전염 ×1.2 (공표 규모와 약정액의 괴리) |
| `pledgedNoSuspensionDays` | 0 → a · 30 → c · **120** → b | a/b/c | `≥30` **그리고** `more_suspensions` 플래그가 서면 T3 **틱 3**에 ΔCI −12, 전염 ×1.35, `reassurance_contradicted` |

`afterTicks: 3`이 핵심이다. `more_suspensions`는 T3의 정지(틱 1~2)가 만들고, 지연효과가 턴 진입(틱 0)에
발화하면 놓친다. 틱 3에 걸어야 "정지 직후에 발표가 뒤집혔다"가 같은 턴 안에서 성립하고,
남은 두 슬라이스(0.17 + 0.30)에 커진 전염이 적용된다.

`more_suspensions`는 `suspend()`가 `failedBanks > count + 1`일 때 세운다 — 즉 **이번 정지가 첫 정지가
아닐 때**. T2의 부산·대전(1 + 2 = 3, `3 > 3` 거짓)에서는 서지 않고 T3의 추가 정지에서 선다.

역사 경로의 대화 경로: `['forum-joint', 'pledgedBackstopTn-6', 'pledgedNoSuspensionDays-120']`.
전문가 경로: `['forum-joint', 'pledgedBackstopTn-6', 'pledgedNoSuspensionDays-0']`.
자동플레이 walker는 목표 옵션에 닿는 응답 중 `expert.rating`이 가장 높은 것을 고르므로,
백스톱 단계의 rating(3→50, **6→85**, 12→30)이 두 경로 모두 6조를 고르게 한다.

### 7.2 T5.D2 — 대주주 자구계획 협상

```
t5-d2-open ─ ask-capital / ask-asset-sale / ask-exit ─▶ t5-d2-amount
            └ ask-none ─────────────────────────────▶ 옵션 c
t5-d2-amount   ─ commitReplies('capitalDemandTn', [0.3, 0.8, 1.5]) ─▶ t5-d2-deadline
t5-d2-deadline ─ commitReplies('capitalDeadlineDays', [30, 60, 120]) ─▶ 옵션 a(≤60) / b(120)
                 └ fund-first ──────────────────────────────────────▶ 옵션 d
```

| 카운터 | 값 | 지연 판정 (T6 진입) |
|---|---|---|
| `capitalDemandTn` | 0.3 / **0.8** / 1.5 | `<0.8`이면 ΔCI −4 (요구 규모가 자본부족액에 미달) |
| `capitalDeadlineDays` | 30 / **60**(전문가) / **120**(역사) | `≤60`이면 기금 +0.6조·ΔCI +4 / `≥120`이면 `forbearanceCost` +0.10, ΔCI −6, 취약군 전염 ×1.1 |

**단계 1을 "무엇을 요구하는가"로 둔 이유**: "서면이냐 구두냐"로 두면 walker가 역사 경로(옵션 b)를
향해 걸을 때 "서면으로 요구했는데 기한은 자율"이라는 모순된 경로를 고른다. 요구 대상을 묻는 질문은
기한과 직교하므로 어느 응답을 골라도 두 옵션 모두와 정합적이다.

역사 경로: `['ask-capital', 'capitalDemandTn-0.8', 'capitalDeadlineDays-120']` — 규모는 맞게 요구했으나
기한이 경영진단(9월) 이후여서 자구계획이 판단 자료가 되지 못했다. 전문가는 `-60`으로만 다르다.

## 8. 시드 변동성 (`scenario.noise`)

```ts
noise: { runoffSigma: 0.14, runoffCap: 0.28, tickerSigma: 0.008, tickerSigmaBp: 2, eventJitter: 1 }
```

크기 노이즈와 틱 지터만 있고 **분기는 만들지 않는다**. `variance: 0`에서는 엔진이 RNG를 아예 당기지
않으므로 체크포인트와 정본 경로는 불변이다. 테스트는 항상 variance 0으로 돈다.

합산 분산이 커지기 때문이다.
